# 检查点

> 跟踪、回溯并总结 Claude 的编辑与对话内容，以管理会话状态。

Claude Code 会在您工作时自动跟踪 Claude 对文件的编辑，让您能够快速撤销更改并在出现偏差时回溯至先前状态。

## 检查点如何工作

当您与 Claude 协作时，检查点功能会在每次编辑前自动捕获代码状态。这个安全网使您能够放心执行雄心勃勃的跨文件任务，因为您随时可以返回到之前的代码状态。

### 自动跟踪

Claude Code 会跟踪其文件编辑工具执行的所有更改：

* 每个用户提示词都会创建新的检查点
* 检查点会跨会话持久保存，因此您可以在恢复的对话中访问它们
* 会话结束后将随会话数据一起自动清理（30 天后，可配置）

### 回溯与总结

运行 `/rewind` 命令，或在提示词输入框为空时连按两次 `Esc` 键，即可打开回溯菜单。

  如果提示词输入框包含文字，双击 `Esc` 会将其清除而不是打开菜单。清除的文字会保存到您的输入历史，因此当您在回溯菜单中完成操作后，按下 `Up` 方向键即可找回它。

回退菜单列出了会话期间您发送的每条提示词。选择您要操作的时间点，然后选择一个操作：

* **恢复代码和对话**：将代码和对话都回退到该时间点
* **恢复对话**：回退到该消息，同时保留当前代码
* **恢复代码**：回退文件更改，同时保留对话
* **从此处总结**：将从该点之后的对话压缩成摘要，释放上下文窗口空间
* **总结至此处**：将该点之前的对话压缩成摘要，保持后续消息不变
* **取消**：返回消息列表，不做任何更改

恢复对话或选择“从此处总结”后，所选消息的原始提示词会恢复到输入字段中，以便您重新发送或编辑。

选择“总结至此处”后，您将停留在对话末尾，输入字段为空。

#### 恢复与总结

恢复选项会回退状态：它们会撤销代码更改、对话历史记录或两者。总结选项会将对话的一部分压缩成由AI生成的摘要，而不会更改磁盘上的文件：

* **从此处总结**：所选消息之前的消息保持不变。所选消息及其之后的所有内容都会被替换为摘要。用于丢弃一段附带讨论，同时完整保留早期上下文。
* **总结至此处**：所选消息之前的消息会被替换为摘要。所选消息及其之后的所有内容保持不变，您将停留在对话末尾。用于压缩早期的设置讨论，同时完整保留近期的工作内容。

在这两种情况下，原始消息都保留在会话记录中，因此 Claude 可以在需要时参考详细信息。您可以输入可选指令来指导摘要的重点。这类似于 `/compact`，但更有针对性：不是总结整个对话，而是选择压缩所选消息的哪一侧。

  **总结**功能让你留在同一个会话中并压缩上下文。如果你想分支出去尝试不同的方法，同时保持原始会话完整，请改用 [fork](/en/sessions#branch-a-session)（`claude --continue --fork-session`）。

## 常见用例

检查点在以下情况尤其有用：

* **探索替代方案**：尝试不同的实现方式而不丢失初始起点
* **从错误中恢复**：快速撤销引入错误或破坏功能的更改
* **迭代功能开发**：在明确可回退至正常状态的前提下尝试各种变体
* **释放上下文空间**：从冗长调试会话的中途开始进行摘要，同时保留初始指令不变

## 限制条件

### Bash命令的更改不受追踪

检查点不会追踪由bash命令修改的文件。例如，如果Claude Code运行了：
```bash
rm file.txt
mv old.txt new.txt
cp source.txt dest.txt
```
这些文件修改无法通过回滚撤销。只有通过 Claude 的文件编辑工具进行的直接文件编辑才会被跟踪。

### 未跟踪的外部更改

检查点仅跟踪当前会话内编辑过的文件。您在 Claude Code 外部手动对文件所做的更改以及其他并行会话的编辑通常不会被捕捉，除非它们恰好修改了与当前会话相同的文件。

### 不能替代版本控制

检查点旨在用于快速的会话级别恢复。对于永久的版本历史记录和协作：

* 请继续使用版本控制（例如 Git）进行提交、分支和长期历史记录管理
* 检查点是补充，但不能取代正确的版本控制
* 可以将检查点视为“本地撤销”，将 Git 视为“永久历史”
