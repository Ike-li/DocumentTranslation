# 桌面应用程序

> 充分利用 Claude Code 桌面版：支持 Git 隔离的并行会话、拖拽式窗格布局、集成终端和文件编辑器、侧边聊天、计算机使用、从手机调度会话、可视化差异审查、应用预览、PR 监控、连接器以及企业配置。

Claude 桌面应用包含三个标签页：**聊天**用于对话，**协作**用于[调度和长时间的自主代理工作](https://claude.com/product/cowork)，而**代码**则用于软件开发。本页是“代码”标签页的参考文档。


    适用于 Intel 和 Apple Silicon 的通用构建



    适用于 x64 处理器


对于 Windows ARM64，请下载 [ARM64 安装程序](https://claude.ai/api/desktop/win32/arm64/setup/latest/redirect?utm_source=claude_code\&utm_medium=docs)。该桌面应用在 Linux 上不可用；请改用 [CLI](/zh/quickstart)。

安装完成后，启动 Claude，登录并点击 **Code** 选项卡。首次在 Windows 上打开时，需要安装 [Git for Windows](https://git-scm.com/downloads/win)；安装后需重启应用。关于首次会话的操作演示，请参阅[入门指南](/zh/desktop-quickstart)。

在 Code 选项卡中，每个对话都是一个 **会话**：它拥有独立的聊天记录、项目文件夹和代码变更，与其他会话无关。侧边栏列出了您的会话，并允许您并行运行多个会话。在一个会话内，您可以：

* [审查并评论差异](#使用差异视图审查更改)，然后[监控由此产生的 PR 通过 CI](#监控拉取请求状态)
* 在 Claude 验证其自身变更时，在嵌入式浏览器中[预览正在运行的应用](#预览你的应用)
* [排列窗格](#安排工作区)，将聊天、差异对比、预览、终端和文件编辑器并置显示
* 提出一个[附带问题](#提出侧边问题而不偏离会话)，该问题会利用会话的上下文而不会使其偏离轨道
* [连接外部工具](#连接外部工具)，如 GitHub、Slack 和 Linear
* 让 Claude [打开应用并控制您的屏幕](#让-claude-使用你的计算机)
* 在您的机器上、[云端](#远程运行长时间任务)或通过 [SSH](#ssh-会话) 运行

关于[计划的定期任务](/zh/desktop-scheduled-tasks)、[键盘快捷键](#键盘快捷键)或[从手机发送任务](#来自-dispatch-的会话)，请参阅链接的页面和章节。如果您已在使用基于终端的 CLI，请查看 [CLI 对比](#来自-cli) 以了解哪些功能得以保留。

## 开始会话

在发送第一条消息前，请在提示词区域配置四项内容：

* **环境**：选择 Claude 的运行位置。选择 **Local** 表示您的机器，选择 **Remote** 表示 Anthropic 托管的云端会话，或选择一个您管理的 [**SSH 连接**](#ssh-会话)。参见[环境配置](#环境配置)。
* **项目文件夹**：选择 Claude 工作所在的文件夹或仓库。对于远程会话，您可以添加[多个仓库](#远程运行长时间任务)。
* **模型**：从发送按钮旁边的下拉菜单中选择一个[模型](/zh/model-config#available-models)。您可以在会话期间更改此设置。
* **权限模式**：通过[模式选择器](#选择权限模式)选择 Claude 拥有多大程度的自主权。您可以在会话期间更改此设置。

输入您的任务并按 **Enter** 开始。每个会话独立跟踪其自身的上下文和变更。

## 处理代码

为 Claude 提供正确的上下文，控制其自主操作的程度，并审查其所做的更改。

### 使用提示词框

输入您希望 Claude 完成的操作，然后按 **Enter** 发送。Claude 会根据您的[权限模式](#选择权限模式)读取项目文件、进行更改并运行命令。您可以在任何时候重新引导 Claude：点击停止按钮立即中断，或者输入纠正信息并按 **Enter** 发送，而无需停止正在运行的操作。Claude 会在当前操作完成后立即读取纠正信息，并在执行下一步之前进行调整。

提示词框旁边的 **+** 按钮让您能够访问文件附件、[技能](#使用技能)、[连接器](#连接外部工具)和[插件](#安装插件)。

### 向提示词添加文件和上下文

提示词框支持两种方式引入外部上下文：

* **@提及文件**：输入 `@` 后跟文件名，将文件添加到对话上下文中。然后 Claude 可以读取并引用该文件。在远程会话中不可用 @提及。
* **附加文件**：使用附件按钮将图像、PDF 和其他文件附加到您的提示词中，或者直接将文件拖放到提示词框中。这对于分享错误截图、设计模型或参考文档非常有用。

### 选择权限模式

权限模式控制 Claude 在会话期间拥有多大程度的自主权：即它在编辑文件、运行命令之前是否询问，或者两者都询问。您可以使用发送按钮旁边的模式选择器随时切换模式。从“询问权限”开始，以确切了解 Claude 的操作，随着您熟悉后，再转到“自动接受编辑”或“规划模式”。

| 模式                  | 设置键              | 行为                                                                                                                                                                                                                                                                     |
| --------------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **询问权限**          | `default`           | Claude 在编辑文件或运行命令之前会进行询问。您会看到差异对比，可以接受或拒绝每个更改。推荐新用户使用。                                                                                                                                                                    |
| **自动接受编辑**      | `acceptEdits`       | Claude 自动接受文件编辑和常见文件系统命令（如 `mkdir`、`touch` 和 `mv`），但在运行其他终端命令之前仍会询问。当您信任文件更改并希望更快迭代时使用此模式。                                                                                                                |
| **规划模式**          | `plan`              | Claude 读取文件并运行命令进行探索，然后提出一个计划而不编辑您的源代码。适用于您想先审查方法的复杂任务。                                                                                                                                                                  |
| **自动**              | `auto`              | Claude 执行所有操作，但带有后台安全检查，以验证是否符合您的请求。在保持监督的同时减少权限提示。在您的 设置 → Claude Code 中启用。参见下面的[可用性要求]。                                                                                      |
| **绕过权限**          | `bypassPermissions` | Claude 运行时不进行任何权限提示，等同于 CLI 中的 `--dangerously-skip-permissions`。在您的 设置 → Claude Code 的“允许绕过权限模式”下启用。仅在沙箱容器或虚拟机中使用此模式。企业管理员可以禁用此选项。                                                               |

`dontAsk` 权限模式仅在 [CLI](/zh/permission-modes#allow-only-pre-approved-tools-with-dontask-mode) 中可用。

<span id="auto-mode-availability" />

自动模式是 Anthropic API 向所有用户提供的研究预览版。在第三方提供商上不可用。它需要 Claude Opus 4.6 或更高版本，或 Sonnet 4.6。

  在复杂任务中启动计划模式，让 Claude 规划好方案后再进行修改。一旦你批准计划，切换到自动接受编辑或询问权限模式来执行它。关于此工作流程的更多内容，请参见[先探索，再计划，然后编码](/zh/best-practices#explore-first-then-plan-then-code)。

远程会话支持自动接受编辑和计划模式。询问权限不可用，因为远程会话默认自动接受文件编辑；绕过权限也不可用，因为远程环境已处于沙箱之中。

企业管理员可以限制可用的权限模式。详情请参阅[企业配置](#企业配置)。

### 预览你的应用

Claude 可以启动开发服务器并打开嵌入式浏览器来验证其更改。此功能既适用于前端 Web 应用，也适用于后端服务器：Claude 可以测试 API 端点、查看服务器日志并迭代修复发现的问题。在大多数情况下，Claude 会在编辑项目文件后自动启动服务器。你也可以随时要求 Claude 进行预览。默认情况下，Claude 会在每次编辑后[自动验证](#自动验证更改)更改。

预览窗格还可以打开项目中的静态 HTML 文件、PDF、图像和视频。点击聊天中的 HTML、PDF、图像或视频路径，即可在预览中打开它。

在预览窗格中，你可以：

* 直接在嵌入式浏览器中与运行的应用交互
* 观看 Claude 自动验证其更改：它会截图、检查 DOM、点击元素、填写表单并修复发现的问题
* 通过会话工具栏中的**预览**下拉菜单启动或停止服务器
* 通过在下拉菜单中选择**持久化会话**，在服务器重启后保持 Cookie 和本地存储，这样开发过程中无需重新登录
* 编辑服务器配置或一次性停止所有服务器

Claude 会根据你的项目创建初始服务器配置。如果你的应用使用自定义开发命令，请编辑 `.claude/launch.json` 以匹配你的设置。完整的参考信息请参阅[配置预览服务器](#配置预览服务器)。

要清除已保存的会话数据，请在设置 → Claude Code 中关闭**持久化预览会话**。要完全禁用预览，请在设置 → Claude Code 中关闭**预览**。

### 使用差异视图审查更改

Claude 修改你的代码后，差异视图允许你在创建拉取请求之前逐文件审查更改。

当 Claude 更改文件时，会出现一个差异统计指示器，显示添加和删除的行数，例如 `+12 -1`。点击此指示器可打开差异查看器，该查看器左侧显示文件列表，右侧显示每个文件的更改内容。

要对特定行进行评论，请点击差异视图中的任意行以打开评论框。输入你的反馈并按 **Enter** 添加评论。在向多行添加评论后，可以一次性提交所有评论：

* **macOS**：按 **Cmd+Enter**
* **Windows**：按 **Ctrl+Enter**

Claude 会读取你的评论并执行要求的更改，这些更改会作为新的差异出现供你审查。

### 审查你的代码

在差异视图中，点击右上角工具栏中的**审查代码**，可以在提交前要求 Claude 评估更改。Claude 会检查当前差异并直接在差异视图中留下评论。你可以回复任何评论或要求 Claude 进行修订。

审查侧重于高信号问题：编译错误、明确的逻辑错误、安全漏洞和明显缺陷。它不会标记样式、格式、已有问题或任何代码检查工具会捕捉到的问题。

### 监控拉取请求状态

当你开启一个拉取请求后，会话中会出现一个 CI 状态栏。Claude Code 使用 GitHub CLI 轮询检查结果并显示失败情况。

* **自动修复**：启用后，Claude 会通过读取失败输出并进行迭代来自动尝试修复失败的 CI 检查。
* **自动合并**：启用后，一旦所有检查通过，Claude 就会合并 PR。合并方法为压缩合并。要使此功能生效，必须在你的 [GitHub 仓库设置中启用自动合并](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-auto-merge-for-pull-requests-in-your-repository)。

使用 CI 状态栏中的**自动修复**和**自动合并**开关来启用任一选项。当 CI 完成时，Claude Code 还会发送桌面通知。要在 PR 合并或关闭后自动归档会话，请在设置 → Claude Code 中开启[自动归档](#使用会话并行工作)。

  PR 监控功能需要你的机器上安装并完成身份验证 [GitHub CLI (`gh`)](https://cli.github.com/)。如果未安装 `gh`，首次尝试创建 PR 时，桌面应用程序会提示你进行安装。

## 安排工作区

代码标签页围绕可自由排列布局的面板构建：聊天、差异、预览、终端、文件、规划、任务和子代理。拖动面板标题栏可重新定位，拖动面板边缘可调整大小。在 macOS 上按 **Cmd+\\**，在 Windows 上按 **Ctrl+\\** 可关闭聚焦的面板。通过会话工具栏中的**视图**菜单可打开更多面板。

  本节中的窗格布局、终端、文件编辑器和视图模式需要 Claude Desktop v1.2581.0 或更高版本。在 macOS 上，请打开 **Claude → Check for Updates**；在 Windows 上，请打开 **Help → Check for Updates** 以进行更新。

### 在终端中运行命令

集成终端允许你在会话中运行命令，无需切换到其他应用。通过 **视图** 菜单或按 macOS 或 Windows 上的 **Ctrl+\`** 键可打开它。终端在你的会话工作目录中打开，并与 Claude 共享相同的环境，因此像 `npm test` 或 `git status` 这样的命令会看到 Claude 正在编辑的相同文件。要打开第二个终端标签页，可点击终端窗格标题栏中的 **+** 或在聊天中右键单击一个文件夹并选择 **在终端中打开**。终端仅在本地会话中可用。

### 打开并编辑文件

点击聊天或差异查看器中的文件路径，可在文件窗格中将其打开。HTML、PDF、图像和视频路径会在[预览窗格](#预览你的应用)中打开。进行即时编辑并点击 **保存** 以写回更改。如果文件自你打开后在磁盘上已更改，窗格会警告你，并允许你覆盖或丢弃。点击 **丢弃** 可撤销你的编辑，或点击窗格标题栏中的路径以复制绝对路径。

文件窗格在本地和 SSH 会话中可用。对于远程会话，请让 Claude 进行更改。

### 在其他应用中打开文件

在聊天、差异查看器或文件窗格中右键单击任何文件路径，可打开上下文菜单：

* **作为上下文附加**：将文件添加到你的下一个提示词
* **用以下程序打开**：在已安装的编辑器（如 VS Code、Cursor 或 Zed）中打开文件
* macOS 上为 **在 Finder 中显示**，Windows 上为 **在资源管理器中显示**：打开包含该文件的文件夹
* **复制路径**：将绝对路径复制到你的剪贴板

### 切换视图模式

视图模式控制聊天记录中显示的详细信息量。通过发送按钮旁的 **聊天记录视图** 下拉菜单切换模式，或在 macOS 或 Windows 上按 **Ctrl+O** 循环切换。

| 模式        | 显示内容                                                  |
| ----------- | -------------------------------------------------------------- |
| **正常**    | 工具调用折叠为摘要，附带完整文本响应                              |
| **详细**    | Claude 执行的每次工具调用、文件读取和中间步骤                     |
| **摘要**    | 仅显示 Claude 的最终响应及其所做的更改                            |

调试 Claude 为何采取特定操作时使用“详细”模式。当你运行多个会话并希望快速浏览结果时使用“摘要”模式。

### 检查使用量

点击模型选择器旁边的使用量环，可查看你当前的上下文窗口使用量和该周期的计划使用量。上下文使用量是按会话计算的；计划使用量则在所有 Claude Code 界面间共享。

## 让 Claude 使用你的计算机

计算机使用功能让 Claude 可以像你一样打开你的应用、控制你的屏幕，并直接在你的机器上工作。让 Claude 在移动模拟器中测试原生应用，与没有命令行界面的桌面工具交互，或自动化仅通过图形用户界面才能完成的操作。

  Claude Code 的电脑使用功能是 macOS 和 Windows 上的研究预览版，需订阅 Pro 或 Max 计划。该功能不适用于 Team 或 Enterprise 计划。Claude Desktop 应用必须保持运行。

默认情况下，Computer use 处于关闭状态。在 Claude 能够控制您的屏幕之前，请先在[设置中启用它](#启用计算机使用功能)。在 macOS 上，您还需要授予“辅助功能”和“屏幕录制”权限。

  与[沙箱Bash工具](/zh/sandboxing)不同，计算机使用在您的实际桌面上运行，可以访问您批准的任何内容。Claude会检查每个操作并标记屏幕上潜在的提示词注入内容，但信任边界有所不同。请参阅[计算机使用安全指南](https://support.claude.com/en/articles/14128542)了解最佳实践。

### 计算机使用功能的适用场景

Claude 有多种方式与应用程序或服务交互，而计算机使用功能是其中最广泛但也最慢的一种。它会优先尝试最精确的工具：

*   如果您有服务的[连接器](#连接外部工具)，Claude 会使用该连接器。
*   如果任务是 Shell 命令，Claude 会使用 Bash。
*   如果任务涉及浏览器操作，并且您已设置好 [Claude in Chrome](/zh/chrome)，Claude 会使用它。
*   如果以上都不适用，Claude 才会使用计算机使用功能。

[按应用划分的访问层级](#应用权限) 进一步强化了这一逻辑：浏览器被限制为仅查看，终端和 IDE 被限制为仅点击操作，这引导 Claude 即便在启用计算机使用功能时，也会优先转向专用工具。屏幕控制功能保留用于处理其他方式无法触及的任务，例如原生应用、硬件控制面板、移动设备模拟器或没有 API 的专有工具。

### 启用计算机使用功能

计算机使用功能默认处于关闭状态。如果您要求 Claude 执行需要此功能的任务，而该功能未开启，Claude 会告知您，如果您在设置中启用计算机使用功能，它就能完成该任务。


    确保您拥有最新版本的 Claude Desktop。请前往 [claude.com/download](https://claude.com/download) 下载或更新，然后重启应用。



    在桌面应用中，进入 **Settings > General**（在 **Desktop app** 下）。找到 **Computer use** 开关并将其打开。在 Windows 上，该开关会立即生效，设置完成。在 macOS 上，请继续下一步操作。

    如果未看到该开关，请确认您使用的是 macOS 或 Windows 并且已订阅 Pro 或 Max 计划，然后更新并重启应用。



    在 macOS 上，需先授予两项系统权限，切换才会生效：

    * **辅助功能**：允许 Claude 执行点击、输入和滚动操作
    * **屏幕录制**：允许 Claude 查看您的屏幕内容

    设置页面会显示每项权限的当前状态。若任一权限被拒绝，点击徽章即可打开对应的系统设置面板。


### 应用权限

首次使用某个应用时，会话中会出现提示。点击 **允许本次会话** 或 **拒绝**。批准在当前会话内有效，或在 [Dispatch 创建的会话](#来自-dispatch-的会话) 中持续 30 分钟。

提示还会显示 Claude 获得的对该应用的控制级别。这些等级由应用类别固定，无法更改：

| 等级         | Claude 可执行的操作                                      | 适用于                      |
| :----------- | :------------------------------------------------------- | :-------------------------- |
| 仅查看       | 在截图中查看应用                                         | 浏览器、交易平台            |
| 仅点击       | 点击和滚动，但不能输入或使用键盘快捷键                   | 终端、IDE                   |
| 完全控制     | 点击、输入、拖动和使用键盘快捷键                         | 其他所有应用                |

对于影响范围较广的应用（如终端、Finder 或文件资源管理器、系统设置），提示中会显示额外警告，以便你了解批准后授予的权限。

你可以在 **设置 > 通用**（**桌面应用** 下）中配置两个设置：

* **拒绝的应用**：将应用添加至此处以无提示拒绝。Claude 仍可能通过已允许应用的操作间接影响被拒绝的应用，但无法直接与该被拒绝应用交互。
* **Claude 完成后恢复隐藏的应用**：Claude 工作时，你的其他窗口会被隐藏，以便它仅与已批准的应用交互。Claude 完成后，隐藏的窗口会被恢复，除非你关闭此设置。

## 管理会话

每个会话都是一个独立的对话，拥有自己的上下文和更改。你可以并行运行多个会话、分支侧边对话、将任务发送到云端，或让 Dispatch 从你的手机为你启动会话。

### 使用会话并行工作

点击侧边栏中的 **+ 新建会话**，或在 macOS 上按 **Cmd+N**，在 Windows 上按 **Ctrl+N**，以并行处理多个任务。按 **Ctrl+Tab** 和 **Ctrl+Shift+Tab** 可在侧边栏中切换会话。对于 Git 仓库，每个会话都使用 [Git 工作树](/zh/worktrees) 获得你项目的独立隔离副本，因此一个会话中的更改在你提交之前不会影响其他会话。

要同时查看两个会话，在 macOS 上按住 **Cmd**，在 Windows 上按住 **Ctrl**，然后点击侧边栏中的一个会话。该会话将在与你已打开会话并排的第二个窗格中打开。拆分处于活动状态时，点击另一个侧边栏会话将替换当前拥有焦点的窗格。在 macOS 上按 **Cmd+\\**，在 Windows 上按 **Ctrl+\\** 可关闭拥有焦点的窗格并返回单会话模式。

工作树默认存储在 `<project-root>/.claude/worktrees/`。你可以在设置 → Claude Code 中的“工作树位置”下将其更改为自定义目录。你还可以设置分支前缀，它会被添加到每个工作树分支名称的前面，这有助于保持 Claude 创建的分支井然有序。要完成时移除工作树，请将鼠标悬停在侧边栏的会话上，然后点击存档图标。要让会话在合并或关闭其拉取请求时自动存档，请在设置 → Claude Code 中开启 **PR 合并或关闭后自动存档**。自动存档仅适用于已完成运行的本地会话。

要将 `.env` 等被 gitignore 的文件包含到新工作树中，请在项目根目录创建 [`.worktreeinclude` 文件](/zh/worktrees#copy-gitignored-files-into-worktrees)。

  会话隔离需要 [Git](https://git-scm.com/downloads)。大多数 Mac 默认已包含 Git。在终端中运行 `git --version` 进行检查。在 Windows 系统上，代码标签页功能需要 Git：[下载 Git for Windows](https://git-scm.com/downloads/win)，安装后重启应用。若遇到 Git 错误，请在 [Cowork 标签页](https://claude.com/product/cowork) 中向 Claude 寻求故障排查帮助。

使用侧边栏顶部的控件，可按状态、项目或环境筛选会话，并按项目对会话进行分组。要重命名会话，请单击活动会话顶部工具栏中的会话标题。要查看上下文使用情况，请参阅[查看使用量](#检查使用量)。当上下文填满时，Claude 会自动总结对话并继续工作。您也可以输入 `/compact` 以提前触发摘要，释放上下文空间。详情请参阅[上下文窗口](/zh/how-claude-code-works#the-context-window)了解压缩机制的工作原理。

当 Code 会话完成任务且您当前未在查看该会话时，桌面应用会发送操作系统通知。

### 提出侧边问题而不偏离会话

侧边聊天允许您向 Claude 提问，该问题使用您会话的上下文，但不会向主对话添加任何内容。当您想了解一段代码、验证一个假设或探索一个想法而不让会话偏离方向时，请使用此功能。

在 macOS 上按 **Cmd+;** 或在 Windows 上按 **Ctrl+;** 打开侧边聊天，或在提示框中输入 `/btw`。侧边聊天可以读取主对话中截至该点的所有内容。完成后，关闭侧边聊天并从上次中断处继续主会话。侧边聊天在本地和 SSH 会话中可用。

### 查看后台任务

任务窗格显示当前会话中运行的后台工作：子代理、后台 Shell 命令和[动态工作流](/zh/workflows)。从 **视图** 菜单打开它，或将其拖入您的布局中。

单击任何条目以在子代理窗格中查看其输出或停止它。要查看其他会话正在做什么，请使用[侧边栏](#使用会话并行工作)。

### 远程运行长时间任务

对于大型重构、测试套件、迁移或其他长时间运行的任务，在启动会话时选择 **远程** 而不是 **本地**。远程会话运行在 Anthropic 的云基础设施上，即使您关闭应用或关闭计算机也会继续运行。您可以随时查看进度或引导 Claude 转向不同方向。您也可以从 [claude.ai/code](https://claude.ai/code) 或 Claude iOS 应用监控远程会话。

远程会话还支持多个仓库。选择云环境后，单击仓库药丸旁边的 **+** 按钮以向会话添加其他仓库。每个仓库都有自己的分支选择器。这对于跨多个代码库的任务（例如更新共享库及其使用者）非常有用。

详情请参阅[Web 版 Claude Code](/zh/claude-code-on-the-web) 了解远程会话的工作原理。

### 在其他界面继续

**继续在...** 菜单可通过会话工具栏右下角的 VS Code 图标访问，允许您将会话移动到另一个界面：

* **Web 版 Claude Code**：将您的本地会话发送到远程继续运行。桌面应用会推送您的分支，生成对话摘要，并创建一个包含完整上下文的新远程会话。然后，您可以选择归档本地会话或保留它。这需要一个干净的工作树，且不适用于 SSH 会话。
* **您的 IDE**：在支持的 IDE 中，在当前工作目录打开您的项目。

### 来自 Dispatch 的会话

[Dispatch](https://support.claude.com/en/articles/13947068) 是与 Claude 的一个持久对话，位于 [Cowork](https://claude.com/product/cowork#dispatch-and-computer-use) 标签页中。您向 Dispatch 发送任务消息，它会决定如何处理。

任务可能以两种方式结束为 Code 会话：您直接请求，例如“打开一个 Claude Code 会话并修复登录错误”，或者 Dispatch 决定该任务是开发工作并自行生成一个。通常路由到 Code 的任务包括修复错误、更新依赖项、运行测试或打开拉取请求。研究、文档编辑和电子表格工作则保留在 Cowork 中。

无论哪种方式，Code 会话都会出现在 Code 标签页的侧边栏中，并带有 **Dispatch** 徽章。当它完成或需要您的批准时，您会收到手机推送通知。

如果您启用了[计算机使用](#让-claude-使用你的计算机)，Dispatch 生成的 Code 会话也可以使用它。这些会话中的应用批准在 30 分钟后过期并会重新提示，而不是像常规 Code 会话那样持续整个会话。

有关设置、配对和 Dispatch 设置，请参阅 [Dispatch 帮助文章](https://support.claude.com/en/articles/13947068)。Dispatch 需要 Pro 或 Max 计划，在 Team 或 Enterprise 计划中不可用。

Dispatch 是您在离开终端时与 Claude 协作的几种方式之一。请参阅[平台与集成](/zh/platforms#work-when-you-are-away-from-your-terminal) 以将其与远程控制、频道、Slack 和定时任务进行比较。

## 扩展 Claude Code

连接外部服务、添加可重用的工作流、自定义 Claude 的行为，并配置预览服务器。要在一处管理连接器、技能和插件，请单击侧边栏中的 **自定义**。

### 连接外部工具

对于本地和 [SSH](#ssh-会话) 会话，单击提示框旁边的 **+** 按钮并选择 **连接器**，以添加如 Google 日历、Slack、GitHub、Linear、Notion 等集成。您可以在会话之前或期间添加连接器。**+** 按钮在远程会话中不可用，但[例程](/zh/routines)可以在创建例程时配置连接器。

要管理或断开连接器，请在桌面应用中转到设置 → 连接器，或从提示框的连接器菜单中选择 **管理连接器**。

连接后，Claude 可以读取您的日历、发送消息、创建问题，并直接与您的工具交互。您可以询问 Claude 您的会话中配置了哪些连接器。

连接器是带有图形化设置流程的 [MCP 服务器](/zh/mcp)。将其用于与受支持服务的快速集成。对于未在连接器中列出的集成，请通过[设置文件](/zh/mcp#installing-mcp-servers)手动添加 MCP 服务器。您也可以[创建自定义连接器](https://support.claude.com/en/articles/11175166-getting-started-with-custom-connectors-using-remote-mcp)。

### 使用技能

[技能](/zh/skills)扩展了 Claude 的能力。Claude 会在相关时自动加载它们，或者您可以直接调用一个：在提示框中输入 `/` 或单击 **+** 按钮并选择 **斜杠命令** 以浏览可用选项。这包括[内置命令](/zh/commands)、您的[自定义技能](/zh/skills#create-your-first-skill)、来自您代码库的项目技能，以及来自任何[已安装插件](/zh/plugins)的技能。选择一个，它会高亮显示在输入字段中。在其后键入您的任务，然后照常发送。

### 安装插件

[插件](/zh/plugins)是可重用的包，为 Claude Code 添加技能、代理、钩子、MCP 服务器和 LSP 配置。您可以在不使用终端的情况下从桌面应用安装插件。

对于本地和 [SSH](#ssh-会话) 会话，单击提示框旁边的 **+** 按钮并选择 **插件** 以查看您已安装的插件及其技能。要添加插件，请从子菜单中选择 **添加插件** 以打开插件浏览器，其中显示来自您配置的[市场](/zh/plugin-marketplaces)（包括官方 Anthropic 市场）的可用插件。选择 **管理插件** 以启用、禁用或卸载插件。

插件可以限定为您的用户帐户、特定项目或仅限本地。如果您的组织集中管理插件，则这些插件在桌面会话中可用，方式与在 CLI 中相同。插件在远程会话中不可用。有关完整的插件参考（包括创建您自己的插件），请参阅[插件](/zh/plugins)。

### 配置预览服务器

Claude 会自动检测您的开发服务器配置，并将其存储在您启动会话时所选文件夹根目录的 `.claude/launch.json` 文件中。预览使用此文件夹作为其工作目录，因此如果您选择了父文件夹，则不会自动检测到拥有自己开发服务器的子文件夹。要处理子文件夹的服务器，要么直接在该文件夹中启动会话，要么手动添加配置。

要自定义服务器启动方式（例如使用 `yarn dev` 而不是 `npm run dev`，或更改端口），请手动编辑文件，或单击预览下拉菜单中的 **编辑配置** 以在您的代码编辑器中打开它。该文件支持带注释的 JSON。
```json
{
  "version": "0.0.1",
  "configurations": [
    {
      "name": "my-app",
      "runtimeExecutable": "npm",
      "runtimeArgs": ["run", "dev"],
      "port": 3000
    }
  ]
}
```
您可以从同一项目定义多个配置以运行不同服务器，例如前端和 API。请参阅下方的[示例](#示例)。

#### 自动验证更改

启用 `autoVerify` 后，Claude 会在编辑文件后自动验证代码更改。它会截图、检查错误，并在完成响应前确认更改有效。

默认情况下自动验证处于开启状态。通过在 `.claude/launch.json` 中添加 `"autoVerify": false` 可以按项目禁用此功能，或通过 **Preview** 下拉菜单进行切换。
```json
{
  "version": "0.0.1",
  "autoVerify": false,
  "configurations": [...]
}
```
禁用时，预览工具仍然可用，您可以随时要求 Claude 进行验证。自动验证会在每次编辑后自动进行。

#### 配置字段

`configurations` 数组中的每个条目接受以下字段：

| 字段                | 类型      | 描述                                                                                                                                                                                                                                                               |
| ------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `name`              | string    | 此服务器的唯一标识符                                                                                                                                                                                                                                               |
| `runtimeExecutable` | string    | 要运行的命令，例如 `npm`、`yarn` 或 `node`                                                                                                                                                                                                                         |
| `runtimeArgs`       | string\[] | 传递给 `runtimeExecutable` 的参数，例如 `["run", "dev"]`                                                                                                                                                                                                           |
| `port`              | number    | 服务器监听的端口。默认为 3000                                                                                                                                                                                                                                       |
| `cwd`               | string    | 相对于项目根目录的工作目录。默认为项目根目录。使用 `${workspaceFolder}` 显式引用项目根目录                                                                                                                                                                         |
| `env`               | object    | 作为键值对的额外环境变量，例如 `{ "NODE_ENV": "development" }`。请勿在此处存放机密信息，因为此文件会提交到您的仓库。要将机密信息传递给您的开发服务器，请在[本地环境编辑器](#本地会话)中设置它们。                                                               |
| `autoPort`          | boolean   | 如何处理端口冲突。见下文                                                                                                                                                                                                                                           |
| `program`           | string    | 要使用 `node` 运行的脚本。参见[何时使用 `program` vs `runtimeExecutable`](#何时使用-program-vs-runtimeexecutable)                                                                                                                                               |
| `args`              | string\[] | 传递给 `program` 的参数。仅在设置了 `program` 时使用                                                                                                                                                                                                               |

##### 何时使用 `program` vs `runtimeExecutable`

使用 `runtimeExecutable` 配合 `runtimeArgs` 来通过包管理器启动开发服务器。例如，`"runtimeExecutable": "npm"` 配合 `"runtimeArgs": ["run", "dev"]` 会运行 `npm run dev`。

当您有一个想直接使用 `node` 运行的独立脚本时，使用 `program`。例如，`"program": "server.js"` 会运行 `node server.js`。通过 `args` 传递额外的标志。

#### 端口冲突

`autoPort` 字段控制当您首选的端口已被占用时会发生什么：

* **`true`**：Claude 会自动查找并使用一个空闲端口。适用于大多数开发服务器。
* **`false`**：Claude 会因错误而失败。当您的服务器必须使用特定端口时使用此选项，例如用于 OAuth 回调或 CORS 白名单。
* **未设置（默认）**：Claude 会询问服务器是否需要那个确切的端口，然后保存您的回答。

当 Claude 选择不同的端口时，它会通过 `PORT` 环境变量将分配的端口传递给您的服务器。

#### 示例

以下配置展示了针对不同项目类型的常见设置：


    该配置通过Yarn在3000端口运行一个Next.js应用。
    ```json
    {
      "version": "0.0.1",
      "configurations": [
        {
          "name": "web",
          "runtimeExecutable": "yarn",
          "runtimeArgs": ["dev"],
          "port": 3000
        }
      ]
    }
    ```



    针对包含前端和 API 服务器的 monorepo，可定义如下多个配置。前端使用 `autoPort: true`，以便在 3000 端口被占用时自动选取空闲端口；而 API 服务器则严格要求使用 8080 端口：

    ```yaml
    # 前端应用
    frontend:
      port: 3000
      autoPort: true

    # API 服务器
    api:
      port: 8080
    ```
    ```json
    {
      "version": "0.0.1",
      "configurations": [
        {
          "name": "frontend",
          "runtimeExecutable": "npm",
          "runtimeArgs": ["run", "dev"],
          "cwd": "apps/web",
          "port": 3000,
          "autoPort": true
        },
        {
          "name": "api",
          "runtimeExecutable": "npm",
          "runtimeArgs": ["run", "start"],
          "cwd": "server",
          "port": 8080,
          "env": { "NODE_ENV": "development" },
          "autoPort": false
        }
      ]
    }
    ```



    要直接运行 Node.js 脚本而不是使用包管理器命令，请使用 `program` 字段：
    ```json
    {
      "version": "0.0.1",
      "configurations": [
        {
          "name": "server",
          "program": "server.js",
          "args": ["--verbose"],
          "port": 4000
        }
      ]
    }
    ```


## 环境配置

您在[启动会话](#开始会话)时选择的环境决定了 Claude 的执行位置以及连接方式：

* **本地**：在您的机器上运行，可直接访问您的文件
* **远程**：在 Anthropic 的云基础设施上运行。即使您关闭应用，会话也会继续。
* **SSH**：在您通过 SSH 连接的远程机器上运行，例如您自己的服务器、云虚拟机或开发容器

### 本地会话

桌面应用并不总是继承您完整的 Shell 环境。在 macOS 上，当您从 Dock 或访达启动应用时，它会读取您的 Shell 配置文件（如 `~/.zshrc` 或 `~/.bashrc`），以提取 `PATH` 和一组固定的 Claude Code 变量，但您在那里导出的其他变量不会被获取。在 Windows 上，应用会继承用户和系统环境变量，但不会读取 PowerShell 配置文件。

要在任何平台上为本地会话和开发服务器设置环境变量，请打开提示词框中的环境下拉菜单，将鼠标悬停在**本地**上，然后点击齿轮图标打开本地环境编辑器。您在此处保存的变量会加密存储在您的机器上，并适用于您启动的每个本地会话和预览服务器。您也可以将变量添加到 `~/.claude/settings.json` 文件的 `env` 键中，不过这些变量仅会传递到 Claude 会话，而不会传递到开发服务器。有关支持变量的完整列表，请参阅[环境变量](/zh/env-vars)。

[扩展思考](/zh/model-config#extended-thinking)默认启用，这可以提高复杂推理任务的性能，但会使用额外的 token。要完全禁用思考，请在本地环境编辑器中将 `MAX_THINKING_TOKENS` 设置为 `0`。在具有[自适应推理](/zh/model-config#adjust-effort-level)功能的模型上，任何其他 `MAX_THINKING_TOKENS` 值都会被忽略，因为自适应推理会控制思考深度。在 Opus 4.6 和 Sonnet 4.6 上，将 `CLAUDE_CODE_DISABLE_ADAPTIVE_THINKING` 设置为 `1` 以使用固定的思考预算；Opus 4.7 及更高版本始终使用自适应推理，没有固定预算模式。

### 远程会话

即使您关闭应用，远程会话也会在后台继续运行。使用量计入您的[订阅计划限制](/zh/costs)，没有单独的计算费用。

您可以创建具有不同网络访问级别和环境变量的自定义云环境。启动远程会话时，选择环境下拉菜单并选择**添加环境**。有关配置网络访问和环境变量的详细信息，请参阅[云环境](/zh/claude-code-on-the-web#the-cloud-environment)。

### SSH 会话

SSH 会话允许您在远程机器上运行 Claude Code，同时使用桌面应用作为您的界面。这对于处理位于云虚拟机、开发容器或具有特定硬件或依赖项的服务器上的代码库非常有用。

要添加 SSH 连接，请在启动会话前点击环境下拉菜单并选择 **+ 添加 SSH 连接**。对话框会询问：

* **名称**：此连接的友好标签
* **SSH 主机**：`user@hostname` 或在 `~/.ssh/config` 中定义的主机
* **SSH 端口**：如果留空则默认为 22，或使用 SSH 配置中的端口
* **身份文件**：您的私钥路径，例如 `~/.ssh/id_rsa`。留空则使用默认密钥或您的 SSH 配置。

添加后，连接将出现在环境下拉菜单中。选择它即可在该机器上启动会话。Claude 在远程机器上运行，可访问其文件和工具。

远程机器必须运行 Linux 或 macOS。首次连接时，桌面应用会在远程机器上自动安装 Claude Code。连接后，SSH 会话支持权限模式、连接器、插件和 MCP 服务器。

#### 为您的团队预配置 SSH 连接

管理员可以通过将 `sshConfigs` 添加到[托管设置](/zh/settings#settings-precedence)文件中，来向团队成员分发 SSH 连接。以这种方式定义的连接会自动出现在每个用户的环境下拉菜单中，并显示为托管状态，因此用户可以选择它们，但无法在应用中编辑或删除它们。

以下示例预配置了一个连接，该连接在远程主机上的 `~/projects` 中打开：
```json
{
  "sshConfigs": [
    {
      "id": "shared-dev-vm",
      "name": "Shared Dev VM",
      "sshHost": "user@dev.example.com",
      "sshPort": 22,
      "sshIdentityFile": "~/.ssh/id_ed25519",
      "startDirectory": "~/projects"
    }
  ]
}
```
每个条目需要 `id`、`name` 和 `sshHost` 字段。`sshPort`、`sshIdentityFile` 和 `startDirectory` 字段为可选。用户还可以将自己的 `sshConfigs` 添加到 `~/.claude/settings.json` 中，这也是通过对话框添加的连接所存储的位置。

#### 限制用户可连接的SSH主机

管理员可以通过在[托管设置](/zh/settings#settings-precedence)文件中添加 `sshHostAllowlist` 来将桌面版的 SSH 会话限制在一组已批准的主机范围内。设置后，用户只能连接到其解析主机名与列表中某个模式匹配的主机。将其设置为空数组可完全禁用 SSH 会话。

以下示例允许连接到 `devboxes.example.com` 下的任何主机以及一个名为 bastion 的特定主机：
```json
{
  "sshHostAllowlist": ["*.devboxes.example.com", "bastion.example.com"]
}
```
模式不区分大小写。`*` 匹配任何主机，`*.example.com` 匹配 `example.com` 和任何子域名。其他模式均为精确匹配。检查是针对通过 `ssh -G` 解析 `~/.ssh/config` 后的主机名进行的，因此只要解析出的 `HostName` 匹配，`Host` 别名以及 `ProxyCommand`/`ProxyJump` 条目都是允许的。

`sshHostAllowlist` 仅从托管设置中读取；用户或项目设置中的值将被忽略。只有 Claude 桌面应用会遵守此设置；Claude Code CLI 和 IDE 扩展程序不会读取它，且它不限制通过 Bash 工具运行的 `ssh` 命令。它控制的是桌面应用连接的主机，而非网络出口流量，因此如果需要严格的边界，请将其与您组织的网络或零信任控制措施结合使用。

## 企业配置

使用团队或企业版计划的组织可以通过管理控制台、托管设置文件和设备管理策略来管理桌面应用行为。

### 管理控制台控件

这些设置通过 [管理设置控制台](https://claude.ai/admin-settings/claude-code) 进行配置：

*   **桌面端代码编写**：控制您组织中的用户是否可以在桌面应用中使用 Claude Code
*   **网页端代码编写**：为您的组织启用或禁用 [网页会话](/zh/claude-code-on-the-web)
*   **远程控制**：为您的组织启用或禁用 [远程控制](/zh/remote-control)
*   **禁用跳过权限模式**：阻止您组织中的用户启用跳过权限模式

### 托管设置

托管设置会覆盖项目和用户设置，并在桌面应用生成 CLI 会话时生效。您可以在组织的 [托管设置](/zh/settings#settings-precedence) 文件中设置这些键，或通过管理控制台远程推送。

| 键名                                       | 描述                                                                                                                                                                                                                                                                                               |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `permissions.disableBypassPermissionsMode` | 设置为 `"disable"` 以阻止用户启用跳过权限模式。                                                                                                                                                                                                                                                        |
| `disableAutoMode`                          | 设置为 `"disable"` 以阻止用户启用 [自动](/zh/permission-modes#eliminate-prompts-with-auto-mode) 模式。同时会从模式选择器中移除自动选项。在 `permissions` 下同样接受此配置。                                                                                                                                |
| `autoMode`                                 | 自定义您组织内自动模式分类器信任和阻止的内容。请参阅 [配置自动模式](/zh/auto-mode-config)。                                                                                                                                                                                                           |
| `sshConfigs`                               | 预配置出现在环境下拉菜单中的 [SSH 连接](#ssh-会话)。用户无法编辑或删除托管连接。                                                                                                                                                                                        |
| `sshHostAllowlist`                         | 将 [SSH 会话](#ssh-会话) 限制为解析后的主机名匹配这些模式之一的主机。空数组将禁用 SSH 会话。仅从托管设置中读取。                                                                                                                                                       |
| `managedMcpServers`                        | 在第三方部署中为所有用户推送 MCP 服务器配置。每个条目指定一个传输协议（`"http"`、`"sse"` 或 `"stdio"`）、连接详情，并可选一个 `toolPolicy` 映射来限制用户可调用该服务器中的哪些工具。仅在第三方 (3P) 桌面部署中可用。                                                                                                    |

部署到每台机器磁盘上的托管设置文件适用于桌面会话。通过管理控制台远程推送的托管设置目前仅适用于 CLI 和 IDE 会话，因此对于桌面部署，请通过 MDM 分发文件或使用上方的 [管理控制台控件](#管理控制台控件)。

`permissions.disableBypassPermissionsMode` 和 `disableAutoMode` 在用户和项目设置中也有效，但将它们置于托管设置中可防止用户覆盖它们。`autoMode` 从用户设置、`.claude/settings.local.json` 和托管设置中读取，但不从已签入的 `.claude/settings.json` 中读取：克隆的仓库无法注入自己的分类器规则。有关仅托管设置的完整列表（包括 `allowManagedPermissionRulesOnly` 和 `allowManagedHooksOnly`），请参阅 [仅托管设置](/zh/permissions#managed-only-settings)。

### 设备管理策略

IT 团队可以通过 macOS 上的 MDM 或 Windows 上的组策略来管理桌面应用。可用策略包括启用或禁用 Claude Code 功能、控制自动更新以及设置自定义部署 URL。

*   **macOS**：使用 Jamf 或 Kandji 等工具，通过 `com.anthropic.Claude` 偏好设置域进行配置
*   **Windows**：通过注册表路径 `SOFTWARE\Policies\Claude` 进行配置

### 认证和 SSO

企业组织可以要求所有用户使用 SSO。有关计划级别的详细信息，请参阅 [认证](/zh/authentication)；有关 SAML 和 OIDC 配置，请参阅 [设置 SSO](https://support.claude.com/en/articles/13132885-setting-up-single-sign-on-sso)。

### 数据处理

Claude Code 在本地会话中本地处理您的代码，或在远程会话中在 Anthropic 的云基础设施上处理。对话和代码上下文会发送到 Anthropic 的 API 进行处理。有关数据保留、隐私和合规性的详细信息，请参阅 [数据处理](/zh/data-usage)。

### 部署

桌面应用可以通过企业部署工具分发：

*   **macOS**：通过 Jamf 或 Kandji 等 MDM，使用 `.dmg` 安装程序进行分发
*   **Windows**：通过 MSIX 包或 `.exe` 安装程序部署。有关包括静默安装在内的企业部署选项，请参阅 [为 Windows 部署 Claude Desktop](https://support.claude.com/en/articles/12622703-deploy-claude-desktop-for-windows)

有关网络配置（如代理设置、防火墙白名单和 LLM 网关），请参阅 [网络配置](/zh/network-config)。

有关完整的企业配置参考，请参阅 [企业配置指南](https://support.claude.com/en/articles/12622667-enterprise-configuration)。

## 来自 CLI？

如果您已经在使用 Claude Code CLI，桌面版运行的是具有图形界面的相同底层引擎。您可以在同一台机器上同时运行两者，甚至可以在同一个项目上运行。两者各自维护独立的会话历史，但通过 CLAUDE.md 文件共享配置和项目记忆。

要将 CLI 会话移至桌面，请在终端中运行 `/desktop`。Claude 会保存您的会话并在桌面应用中打开它，然后退出 CLI。当您使用 Claude 订阅登录时，此命令在 macOS 和 Windows 上可用。API 密钥认证或 Bedrock、Vertex、Foundry 环境下不可用。

  何时使用桌面版与命令行：当您希望在一个窗口中管理多个并行会话、并排排列面板或直观地审查更改时，请使用桌面版。当您需要脚本编写、自动化功能或偏好终端工作流程时，请使用命令行。

### 共享配置

桌面端和 CLI 读取相同的配置文件，因此您的设置可以无缝迁移：

* 您项目中的 **[CLAUDE.md](/zh/memory)** 和 `CLAUDE.local.md` 文件会被两者共同使用
* 在 `~/.claude.json` 或 `.mcp.json` 中配置的 **[MCP 服务器](/zh/mcp)** 可在两者中使用
* 在设置中定义的 **[钩子](/zh/hooks)** 和 **[技能](/zh/skills)** 适用于两者
* `~/.claude.json` 和 `~/.claude/settings.json` 中的 **[设置](/zh/settings)** 是共享的。`settings.json` 中的权限规则、允许的工具和其他设置适用于桌面端会话。
* **模型**：Sonnet、Opus 和 Haiku 在两者中均可用。在桌面端，通过发送按钮旁的下拉菜单选择模型。您可以在会话中通过同一下拉菜单切换模型。

  **MCP 服务器：桌面聊天应用与 Claude Code 的区别**：为 Claude Desktop 聊天应用在 `claude_desktop_config.json` 中配置的 MCP 服务器与 Claude Code 是相互独立的，不会出现在代码选项卡中。要在 Claude Code 中使用 MCP 服务器，请在 `~/.claude.json` 或项目的 `.mcp.json` 文件中进行配置。详情请参阅 [MCP 配置](/zh/mcp#installing-mcp-servers)。

### 桌面版中不可用的功能

以下功能仅在 CLI 或 VS Code 扩展中可用：

* **终端对话命令**：在终端中打开交互面板的内置命令（如 `/permissions`、`/config`、`/agents` 和 `/doctor`）在代码标签页中不可用，并会回复 `isn't available in this environment`。请直接编辑[设置文件](/zh/settings)来管理权限规则和配置，或从独立的 CLI 运行该命令。

## 故障排除

以下部分涵盖桌面应用特有的问题。对于聊天中出现的运行时 API 错误（如 `API Error: 500`、`529 Overloaded`、`429` 或 `Prompt is too long`），请参阅[错误参考](/zh/errors)。这些错误及其修复方法在 CLI、桌面版和网页版中是相同的。

### 检查您的版本

要查看您正在运行的桌面应用版本：

* **macOS**：点击菜单栏中的 **Claude**，然后点击 **关于 Claude**
* **Windows**：点击 **帮助**，然后点击 **关于**

点击版本号可将其复制到剪贴板。

### 代码标签页中的 403 或身份验证错误

如果您在使用代码标签页时看到 `Error 403: Forbidden` 或其他身份验证失败：

1. 从应用菜单注销并重新登录。这是最常见的修复方法。
2. 验证您拥有有效的付费订阅：Pro、Max、Team 或 Enterprise。
3. 如果 CLI 可用但桌面版不可用，请完全退出桌面应用（而不仅仅是关闭窗口），然后重新打开并登录。
4. 检查您的互联网连接和代理设置。

### 启动时屏幕空白或卡住

如果应用打开但显示空白或无响应的屏幕：

1. 重启应用。
2. 检查待处理的更新。应用在启动时会自动更新。
3. 在 Windows 上，在 **Windows 日志 → 应用程序**下的事件查看器中检查崩溃日志。

### "加载会话失败"

如果看到 `Failed to load session`，所选文件夹可能已不存在，Git 仓库可能需要未安装的 Git LFS，或者文件权限可能阻止访问。请尝试选择其他文件夹或重启应用。

### 会话找不到已安装的工具

如果 Claude 无法找到 `npm`、`node` 或其他 CLI 命令等工具，请验证这些工具在您常规终端中是否正常工作，检查您的 shell 配置文件是否正确设置了 PATH，并重启桌面应用以重新加载环境变量。

### Git 和 Git LFS 错误

在 Windows 上，Git 是代码标签页启动本地会话所必需的。如果看到 "Git is required"，请安装 [Git for Windows](https://git-scm.com/downloads/win) 并重启应用。

如果看到 "Git LFS is required by this repository but is not installed"，请从 [git-lfs.com](https://git-lfs.com/) 安装 Git LFS，运行 `git lfs install`，然后重启应用。

### Windows 上 MCP 服务器不工作

如果在 Windows 上 MCP 服务器开关无响应或服务器连接失败，请检查服务器是否在设置中正确配置，重启应用，在任务管理器中验证服务器进程是否正在运行，并检查服务器日志以查找连接错误。

### 应用无法退出

* **macOS**：按 Cmd+Q。如果应用无响应，请使用 Cmd+Option+Esc 强制退出，选择 Claude，然后点击强制退出。
* **Windows**：使用 Ctrl+Shift+Esc 打开任务管理器以结束 Claude 进程。

### Windows 特定问题

* **安装后 PATH 未更新**：打开一个新的终端窗口。PATH 更新仅适用于新的终端会话。
* **并发安装错误**：如果看到关于另一个正在进行的安装的错误但实际上没有，请尝试以管理员身份运行安装程序。

### 在 CLI 中打开时出现"分支尚不存在"

远程会话可能会创建您本地机器上不存在的分支。点击会话工具栏中的分支名称将其复制，然后在本地获取它：
```bash
git fetch origin <branch-name>
git checkout <branch-name>
```
