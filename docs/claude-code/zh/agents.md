# 并行运行代理

> 比较 Claude Code 同时处理多项任务的方式：子代理、代理视图、代理团队和动态工作流。

[子代理](/en/sub-agents)、[代理视图](/en/agent-view)、[代理团队](/en/agent-teams)和[动态工作流](/en/workflows)各以不同方式实现工作并行化。选择哪种方式取决于您是希望亲自参与每个对话、将任务委派后稍后再查看，还是让 Claude 为您协调一组工作者。

| 方式                              | 提供的功能                                                                                                                                                              | 适用场景                                                                                                                                                                                            |
| :--------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [子代理](/en/sub-agents)           | 在同一会话中委派的工作者，它们在自己的上下文中执行辅助任务并返回摘要                                                                                                 | 辅助任务可能会将大量您不会再查阅的搜索结果、日志或文件内容涌入主对话中                                                                                                                               |
| [代理视图](/en/agent-view)         | 一个用于派发和监控后台运行会话的屏幕，通过 `claude agents` 打开。研究预览版                                                                                          | 您拥有多个独立任务，希望将其委派出去，能一眼查看状态，仅在某个任务需要时才介入                                                                                                                       |
| [代理团队](/en/agent-teams)        | 多个协调的会话，拥有共享任务列表和代理间消息传递，由一个主导者管理。实验性功能，默认禁用                                                                               | 您希望 Claude 将项目拆分、分配，并保持工作者之间的同步                                                                                                                                              |
| [动态工作流](/en/workflows)        | 一个运行众多子代理并交叉核对结果的脚本，适用于单次无法协调或需要多次处理的大型工作。研究预览版                                                                         | 工作量超出了少量子代理的能力，或者您需要交叉验证发现：例如整个代码库的审计、500个文件的迁移、交叉核对的研究，或从多个角度起草的计划                                                                   |

在所有方式中，工作者都是 Claude 会话。若要使用不同的工具，请将其作为 [MCP 服务器](/en/mcp)提供给 Claude。

还有两种工具支持此类工作，但它们本身并非运行代理的方式：

* [工作树](/en/worktrees) 为每个会话提供独立的 Git 工作区，因此并行会话永远不会编辑相同的文件。用于您自己运行的会话。代理视图会自动将派发的每个会话移入其自己的工作树中，您生成的子代理也可以各自获得一个。
* [`/batch`](/en/commands) 是一项[技能](/en/skills)，它让 Claude 将一个大的变更拆分为 5 到 30 个由工作树隔离的子代理，每个子代理都会打开一个拉取请求。这是子代理和工作树的打包使用，并非一种单独的协调风格。

其他一些功能可以在您不逐步驱动的情况下运行 Claude，但它们解决的问题与在代理之间分配工作不同：

* [后台 bash 命令](/en/interactive-mode#background-bash-commands) 运行单个 shell 命令而不会阻塞对话。它不会生成代理。
* [派生的子代理](/en/sub-agents#fork-the-current-conversation) 是继承您完整对话上下文（而非从头开始）的子代理。这是一种生成子代理的方式，而不是一个独立的界面。
* [例程](/en/routines) 在 Anthropic 的云端按计划运行会话，而不是在您的机器上并行运行。

  同时运行多个会话或子代理会成倍增加token用量。详情请参阅[费用说明](/en/costs)了解用量和速率限制信息。

## 选择一种方法

正确的方法取决于谁协调工作、工作者是否需要通信以及他们是否编辑相同的文件：

* **谁协调工作？**
  * Claude 在单个对话中委派并收集结果：[子代理](/en/sub-agents)
  * 你移交独立任务并稍后检查：[代理视图](/en/agent-view)
  * Claude 规划、分配并监督一组工作者：[代理团队](/en/agent-teams)（实验性，默认禁用）
  * 脚本持有计划，而非 Claude 的逐轮判断：[动态工作流](/en/workflows)。参见 [工作流与子代理和技能的比较](/en/workflows#when-to-use-a-workflow)
* **工作者之间需要沟通吗？** 子代理将结果报告给生成它们的对话，代理视图会话仅向你报告。代理团队中的队友共享任务列表并直接互相发送消息。
* **任务涉及相同的文件吗？** 使用 [工作树](/en/worktrees) 隔离工作。你运行的子代理和会话可以各自使用一个单独的工作树。代理团队不会将队友隔离在工作树中，因此需要 [划分工作](/en/agent-teams#avoid-file-conflicts)，使每个队友拥有不同的文件集。

## 检查运行中的工作

检查运行中工作的命令取决于你使用的方法：

* 对于后台会话，`claude agents` 打开 [代理视图](/en/agent-view)：一个屏幕显示每个会话、其状态以及哪些需要你的输入。
* 对于当前会话中的子代理，`/agents` 打开一个面板，其中 **运行中** 标签页列出了活跃的子代理，**库** 标签页用于 [创建和编辑自定义子代理](/en/sub-agents#use-the-%2Fagents-command)。尽管名称相似，这与 `claude agents` 是分开的。
* 对于当前会话后台运行的任何内容，`/tasks` 列出每个项目，让你可以检查、附加或停止它。
* 对于动态工作流，`/workflows` 列出运行中和已完成的工作流、它们所处的阶段以及有多少代理已完成。

要查看所有会话的桌面视图，请参阅 [桌面应用中的并行会话](/en/desktop#work-in-parallel-with-sessions)。
