# 让 Claude 持续朝目标工作

> 使用 /goal 设置完成条件，Claude 会跨轮次持续工作直到条件满足。

`/goal` 需要 Claude Code v2.1.139 或更高版本。

`/goal` 命令设置一个完成条件，Claude 会持续朝着该目标工作，无需你每步都给出提示。每轮结束后，一个小型快速模型会检查条件是否满足。如果不满足，Claude 会开始新一轮工作，而不是将控制权交还给你。条件满足后，目标会自动清除。

对于具有可验证结束状态的大型任务，可以使用目标：

* 将模块迁移到新 API，直到所有调用点编译通过且测试通过
* 实现设计文档，直到所有验收标准满足
* 将大文件拆分为专注的模块，直到每个模块都在大小预算内
* 处理带标签的问题积压，直到队列清空

## 比较其他自主工作流

三种方案可在提示之间保持当前会话持续运行。根据什么应该启动下一轮来选择：

| 方案                                                                | 下一轮启动时机             | 停止时机                                        |
| :------------------------------------------------------------------ | :------------------------- | :---------------------------------------------- |
| `/goal`                                                             | 上一轮结束时               | 模型确认条件已满足                              |
| [`/loop`](/zh/scheduled-tasks#run-a-prompt-repeatedly-with-%2Floop) | 时间间隔到达时             | 你停止它，或 Claude 决定工作完成                |
| [停止钩子](/zh/hooks-guide#prompt-based-hooks)                      | 上一轮结束时               | 你自己的脚本或提示词决定                        |

`/goal` 和停止钩子都在每轮结束后触发。`/goal` 是会话级的快捷方式：你输入一个条件，它仅在当前会话中生效。停止钩子存在于你的设置文件中，适用于其作用域内的每个会话，可以运行脚本进行确定性检查，或运行提示词进行模型评估。

[自动模式](/zh/auto-mode-config)本身只在单轮内批准工具调用，但不会启动新一轮。Claude 在判断工作完成后会停止。`/goal` 添加了一个独立的评估器，在每轮结束后检查你的条件，因此完成是由一个全新的模型而非正在工作的模型来决定的。两者是互补的：自动模式消除了逐工具的提示，而 `/goal` 消除了逐轮的提示。

以上方案保持当前会话运行。你也可以调度独立于任何打开会话的工作，如每夜测试或早晨分诊。查看[调度选项](/zh/scheduled-tasks#compare-scheduling-options)了解云例程和桌面计划任务。

## 使用 `/goal`

每个会话只能有一个活跃的目标。同一个命令根据参数设置、检查和清除目标。

### 设置目标

运行 `/goal` 后跟你想满足的条件。如果已有活跃目标，新目标会替换它。

```text
/goal all tests in test/auth pass and the lint step is clean
```

设置目标会立即开始一轮工作，条件本身即为指令。你不需要单独发送提示词。目标活跃期间，`◎ /goal active` 指示器会显示目标已运行了多长时间。

每轮结束后，评估器会返回一个简短的原因，解释条件是否满足。最近的原因会出现在状态视图和对话记录中，以便你了解 Claude 下一步的工作方向。

目标会持续运行，直到条件满足或你运行 `/goal clear`。不带参数运行 `/goal` 可查看已花费的轮次和 token 数。

### 编写有效条件

[评估器](#评估工作原理)根据 Claude 在对话中呈现的内容来判断你的条件。它不会独立运行命令或读取文件，因此请将条件编写为 Claude 自身输出可以证明的内容。"test/auth 中所有测试通过"是有效的，因为 Claude 运行了测试，结果会落在对话记录中供评估器读取。

跨多轮持续有效的条件通常具有：

* **一个可衡量的结束状态**：测试结果、构建退出码、文件数量、空队列
* **明确的检查方式**：Claude 如何证明，如 "`npm test` 退出码为 0" 或 "`git status` 干净"
* **重要的约束**：在此过程中不得更改的内容，如"不修改其他测试文件"

条件最多可达 4,000 个字符。

要限制目标运行时间，可在条件中包含轮次或时间子句，如 `or stop after 20 turns`。Claude 每轮会报告针对该子句的进度，评估器根据对话进行判断。

### 检查状态

不带参数运行 `/goal` 查看当前状态。

```text
/goal
```

如果有活跃目标，状态显示：

* 条件
* 已运行多长时间
* 已评估的轮次
* 当前 token 消耗
* 评估器最近的原因

如果没有活跃目标，但会话中之前已达成目标，状态会显示已达成的条件及其持续时间、轮次和 token 消耗。

### 清除目标

运行 `/goal clear` 在条件满足前移除活跃目标。

```text
/goal clear
```

`stop`、`off`、`reset`、`none` 和 `cancel` 都是 `clear` 的别名。运行 `/clear` 开始新会话也会移除任何活跃目标。

### 恢复时保留活跃目标

会话结束时仍然活跃的目标会在你使用 `--resume` 或 `--continue` 恢复会话时恢复。条件会延续，但轮次计数、计时器和 token 消耗基线都会在恢复时重置。已达成或已清除的目标不会恢复。

### 非交互运行

`/goal` 可在[非交互模式](/zh/headless)、[桌面应用](/zh/desktop)和[远程控制](/zh/remote-control)中使用。使用 `-p` 设置目标会在单次调用中运行循环直到完成：

```bash
claude -p "/goal CHANGELOG.md has an entry for every PR merged this week"
```

使用 Ctrl+C 中断进程可在条件满足前停止非交互目标。

## 评估工作原理

`/goal` 是会话级[基于提示词的停止钩子](/zh/hooks#prompt-based-hooks)的封装。每次 Claude 完成一轮工作后，条件和迄今为止的对话会发送给你配置的[小型快速模型](/zh/model-config)，默认为 Haiku。模型返回是或否的决定以及简短的原因。"否"告诉 Claude 继续工作，并将原因作为下一轮的指导。"是"清除目标并在对话记录中记录已达成的条目。

评估器在你的会话所配置的提供商上运行。它不调用工具，因此只能判断 Claude 已在对话中呈现的内容。

评估 token 按为你的提供商配置的小型快速模型计费，通常与主轮消耗相比可忽略不计。

## 要求

`/goal` 仅在你已接受信任对话的工作区中运行，因为评估器是钩子系统的一部分。当任何设置级别设置了 [`disableAllHooks`](/zh/hooks#disable-or-remove-hooks) 或托管设置中设置了 [`allowManagedHooksOnly`](/zh/settings#hook-configuration) 时，`/goal` 也不可用。在每种情况下，命令都会告诉你原因，而不是静默不执行。
