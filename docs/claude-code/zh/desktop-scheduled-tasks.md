# 在 Claude Code Desktop 中安排定期任务

> 在 Claude Code Desktop 中设置定期任务，让 Claude 自动执行每日代码审查、依赖项审计或晨间简报等周期性工作。

定期任务会在您选择的时间和频率自动启动一个新会话。可用于执行日常工作，如每日代码审查、依赖项更新检查或从日历和收件箱获取信息的晨间简报。

桌面应用的 **“例程”** 页面允许您创建本地定时任务和远程[例程](/zh/routines)。本地任务在您的机器上运行，可直接访问您的文件和工具，但仅在应用处于打开状态且计算机保持唤醒时触发。远程例程则在 Anthropic 托管的云基础设施上运行，即使您的计算机关闭也能执行，还可以在 API 调用或 GitHub 事件时触发。本页介绍本地定时任务；有关远程例程及其触发选项，请参见[例程](/zh/routines)。

## 对比调度选项

Claude Code 提供了三种安排定期或一次性工作的方式：

|                            | [云端](/zh/routines)          | [桌面端](/zh/desktop-scheduled-tasks) | [`/loop`](/zh/scheduled-tasks)      |
| :------------------------- | :----------------------------- | :------------------------------------- | :---------------------------------- |
| 运行位置                   | Anthropic 云                  | 您的机器                               | 您的机器                            |
| 需要机器开机               | 否                             | 是                                     | 是                                  |
| 需要会话打开               | 否                             | 否                                     | 是                                  |
| 跨重启持续                 | 是                             | 是                                     | 若未过期，在 `--resume` 时恢复     |
| 访问本地文件               | 否（全新克隆）                 | 是                                     | 是                                  |
| MCP 服务器                 | 按任务配置的连接器             | [配置文件](/zh/mcp) 和连接器           | 继承自会话                          |
| 权限提示                   | 否（自主运行）                 | 可按任务配置                           | 继承自会话                          |
| 可定制调度                 | 通过 CLI 中的 `/schedule`      | 是                                     | 是                                  |
| 最小间隔                   | 1 小时                         | 1 分钟                                 | 1 分钟                              |

  使用**云端任务**来运行无需依赖本地机器的可靠工作。需要访问本地文件和工具时，请使用**桌面任务**。在会话中进行快速轮询时，请使用 **`/loop`**。



  默认情况下，定时任务会在工作目录的当前状态下运行，包括未提交的更改。创建任务时启用工作树切换开关，可为每次运行提供独立的 Git 工作树，其工作方式与[并行会话](/zh/desktop#work-in-parallel-with-sessions)相同。

## 创建计划任务

在侧边栏中点击 **Routines**，然后点击 **New routine** 并选择 **Local**。配置以下字段：

| 字段         | 描述                                                                                                                                                                                                                                                               |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Name         | 任务的标识符。将转换为小写的 kebab-case 格式并用作磁盘上的文件夹名称。在您的所有任务中必须唯一。                                                                                                                                                                     |
| Description  | 任务列表中显示的简短摘要。                                                                                                                                                                                                                                         |
| Instructions | 任务运行时 Claude 应该做什么。像您在提示框中编写任何消息一样编写此内容。指令输入包含权限模式和模型的选择器，在其下方您可以选择工作文件夹以及是否在隔离的工作树中运行。                                                                                            |
| Schedule     | 任务的运行频率。请参阅下方的[调度选项](#调度选项)。                                                                                                                                                                                                         |

保存任务前需要先指定一个文件夹。如果您尚未信任该文件夹，桌面应用会在保存前提示您进行信任。

您也可以在任何会话中通过描述您的需求来创建任务。例如，"set up a daily code review that runs every morning at 9am" 会创建一个定期任务，而 "remind me at 3pm tomorrow to check the deploy" 会创建一个一次性任务，触发后会自动禁用。

## 调度选项

从“Schedule”控件中选择一个预设选项：

* **Manual**：无调度，仅当您点击 **Run now** 时运行。适用于保存您按需触发的提示词
* **Hourly**：每小时运行一次
* **Daily**：显示一个时间选择器，默认为本地时间上午 9:00
* **Weekdays**：与 Daily 相同，但跳过周六和周日
* **Weekly**：显示一个时间选择器和一个日期选择器

对于选择器未提供的间隔，例如每 15 分钟、每月第一天或特定未来时间的单次运行，请在任何桌面会话中要求 Claude 设置调度。使用自然语言；例如，"schedule a task to run all the tests every 6 hours"。

## 计划任务如何运行

计划任务在您的机器上运行。当应用打开时，桌面应用每分钟检查一次调度，并在任务到期时启动一个全新的会话，这与您打开的任何手动会话无关。每个任务在计划时间后会有几分钟的小延迟，以错开 API 流量。该延迟是确定性的：同一个任务总是在相同的偏移时间启动。

当任务触发时，您会收到桌面通知，并且在侧边栏的 **Scheduled** 部分下会出现一个新会话。打开它可以查看 Claude 做了什么、审查更改或响应权限提示。该会话与其他会话的工作方式相同：Claude 可以编辑文件、运行命令、创建提交和打开拉取请求。

任务仅在桌面应用运行且计算机处于唤醒状态时运行。如果计算机在计划时间睡眠，则会跳过该次运行。要防止空闲休眠，请在 **Settings** 的 **Desktop app → General** 下启用 **Keep computer awake**。合上笔记本电脑盖仍会使其进入睡眠。对于需要在计算机关闭时运行、或应由 API 调用或 GitHub 事件触发的任务，请创建远程 [routine](/zh/routines)。

## 错过的运行

当应用启动或计算机唤醒时，桌面应用会检查每个任务在过去七天内是否错过了任何运行。如果有，桌面应用会精确地为最近错过的时间启动一次补运行，并丢弃更早的。一个错过了六天的每日任务会在唤醒时运行一次。当补运行开始时，桌面应用会显示通知。

在编写提示词时请记住这一点。如果您的计算机全天睡眠，计划在上午 9 点运行的任务可能会在晚上 11 点运行。如果时间很重要，请在提示词本身中添加防护措施，例如："Only review today's commits. If it's after 5pm, skip the review and just post a summary of what was missed."

## 计划任务的权限

每个任务都有其自己的权限模式，您可以在创建或编辑任务时进行设置。`~/.claude/settings.json` 中的允许规则也适用于计划任务会话。如果任务以“Ask”模式运行，并且需要运行其无权使用的工具，运行将暂停，直到您批准为止。该会话会保持在侧边栏中打开，以便您稍后回应。

为避免暂停，请在创建任务后点击 **Run now**，留意权限提示，并为每个提示选择“always allow”。该任务的未来运行将自动批准相同的工具，而无需提示。您可以从任务的详细信息页面审查和撤销这些批准。

## 管理计划任务

在 **Routines** 列表中单击一个任务以打开其详细信息页面。在这里您可以：

* **Run now**：立即启动任务，无需等待下一个计划时间
* **Status**：在“Active”和“Paused”之间切换，以暂停或恢复计划运行而不删除任务
* **Edit**：更改指令、调度、文件夹或其他设置
* **Review history**：查看每一次过去的运行，包括跳过的运行。将鼠标悬停在跳过的条目上可查看原因：您的计算机睡眠、上一次运行仍在进行中、或其他计划任务已在运行。点击 **Show more** 可加载更早的条目。
* **Review allowed permissions**：从 **Always allowed** 面板中查看并撤销此任务保存的工具批准
* **Delete**：删除任务并归档其创建的所有会话。确认对话框中会出现一个 **Also delete files on disk** 复选框；勾选它可同时从 `~/.claude/scheduled-tasks/` 中移除该任务的 `SKILL.md` 文件和相关数据。

您也可以通过在任何桌面会话中要求 Claude 来列出、创建、编辑和暂停任务。例如，"pause my dependency-audit task" 或 "show me my scheduled tasks." 要删除任务，请使用其详细信息页面上的 **Delete** 按钮。

计划任务还可以在运行中的会话内使用 `update_scheduled_task` MCP 工具修改其自身的调度或提示词。这允许任务根据其发现的内容重新调度自身，例如，当它检测到已创建发布分支时，将代码审查重新调度至更早时间运行。

要编辑磁盘上的任务提示词，请打开 `~/.claude/scheduled-tasks/<task-name>/SKILL.md`（或如果设置了 [`CLAUDE_CONFIG_DIR`](/zh/env-vars) 则在其下）。该文件对 `name` 和 `description` 使用 YAML 前置元数据，提示词作为正文。更改将在下次运行时生效。调度、文件夹、模型和启用状态不在此文件中：请通过编辑表单或询问 Claude 进行更改。
