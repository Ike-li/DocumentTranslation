# 通过快速模式加速响应

> 切换快速模式，让 Claude Code 中的 Opus 响应更迅速。

  快速模式目前处于[研究预览](#研究预览)阶段。该功能、定价及可用性可能会根据反馈进行调整。

快速模式是为Claude Opus设计的高速配置，能让模型响应速度提升最高2.5倍，但会消耗更高的每token成本。在需要快速迭代或实时调试等交互场景时，可通过`/fast`命令开启此模式；当成本比延迟更重要时，则可关闭该模式。

快速模式并非独立模型，而是采用相同Claude Opus模型但通过优化API配置，在牺牲部分成本效率的前提下优先保障响应速度。您将获得完全相同的质量与功能，只是响应更快。快速模式适用于Opus 4.8、Opus 4.7和Opus 4.6版本，不支持Sonnet、Haiku及其他模型。

  Opus 4.6 的快速模式已被弃用，并将在 Opus 4.8 发布大约 30 天后移除。移除后，Opus 4.6 上的快速模式将以标准速度回退到标准定价。请迁移到 Opus 4.8 或 Opus 4.7 以保持加速。



  快速模式需要 Claude Code v2.1.36 或更高版本。请使用 `claude --version` 检查您的版本。

**需要了解的信息：**

* 在 Claude Code CLI 中使用 `/fast` 切换快速模式。VS Code 扩展中不支持快速模式。
* 快速模式在 Opus 4.8 上的价格为 $10/$50 MTok，在 Opus 4.7 和 Opus 4.6 上的价格为 $30/$150 MTok。
* 适用于所有订阅计划（Pro/Max/Team/Enterprise）和 Claude Console 的 Claude Code 用户。
* 对于订阅计划（Pro/Max/Team/Enterprise）的 Claude Code 用户，快速模式仅通过使用额度可用，不计入订阅速率限制。

本页面介绍如何[切换快速模式](#切换快速模式)、其[成本权衡](#理解成本权衡)、[何时使用](#决定何时使用快速模式)、[要求](#要求)、[按会话选择加入](#要求每个会话单独选择启用)以及[速率限制行为](#处理速率限制)。

## 切换快速模式

通过以下任一方式切换快速模式：

* 输入 `/fast` 并按 Tab 键以开启或关闭
* 在您的[用户设置文件](/zh/settings)中设置 `"fastMode": true`

默认情况下，快速模式在会话之间保持开启状态。管理员可以配置快速模式在每个会话重置。详见[要求按会话选择加入](#要求每个会话单独选择启用)。

为了获得最佳的成本效益，请在会话开始时启用快速模式，而不是在对话中途切换。详见[理解成本权衡](#理解成本权衡)。

当您启用快速模式时：

* 如果您使用的是其他模型，Claude Code 将自动切换到 Opus
* 您将看到确认消息："快速模式已开启"
* 快速模式激活期间，提示词旁边会出现一个小型 `↯` 图标
* 随时再次运行 `/fast` 可检查快速模式是开启还是关闭

当您再次使用 `/fast` 禁用快速模式时，您将保持使用 Opus。模型不会恢复到您之前的模型。要切换到不同的模型，请使用 `/model`。

在 Claude Code v2.1.154 及更高版本中，快速模式默认为 Opus 4.8。在 v2.1.142 至 v2.1.153 版本中，快速模式默认为 Opus 4.7。要将快速模式固定为 Opus 4.6，请设置 `CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE=1`；当 Opus 4.6 的快速模式停用时，此覆盖将被移除。

## 理解成本权衡

快速模式的每 token 价格高于标准 Opus，乘数因模型而异：

| 模型                   | 输入 (MTok) | 输出 (MTok) |
| --------------------- | ------------ | ------------- |
| Opus 4.8              | \$10         | \$50          |
| Opus 4.7 和 Opus 4.6  | \$30         | \$150         |

快速模式定价在整个 100 万 token 上下文窗口内是固定的。有关用于比较的标准 Opus 费率，请参见 [Claude 定价参考](https://platform.claude.com/docs/en/about-claude/pricing)。

当您在对话中途切换到快速模式时，您需要为整个对话上下文支付完整的快速模式未缓存输入 token 价格。这比您从一开始就启用快速模式的成本更高。

## 决定何时使用快速模式

快速模式最适合响应延迟比成本更重要的交互式工作：

* 代码更改的快速迭代
* 实时调试会话
* 截止日期紧迫的时间敏感型工作

标准模式更适合：

* 速度不太重要的长时间自主任务
* 批处理或 CI/CD 流水线
* 对成本敏感的工作负载

### 快速模式与努力级别

快速模式和努力级别都会影响响应速度，但方式不同：

| 设置                 | 效果                                                                           |
| ------------------- | -------------------------------------------------------------------------------- |
| **快速模式**         | 相同的模型质量，更低的延迟，更高的成本                                           |
| **较低的努力级别**   | 思考时间更短，响应更快，在复杂任务上可能质量较低                                 |

您可以同时使用两者：在简单任务上，结合快速模式和较低的[努力级别](/zh/model-config#adjust-effort-level)以获得最高速度。

## 要求

快速模式需要满足以下所有条件：

* **仅限 Anthropic API 或订阅计划**：快速模式可通过 Anthropic Console API 和使用使用额度的 Claude 订阅计划使用。在 Amazon Bedrock、Google Vertex AI、Microsoft Azure Foundry 或 AWS 上的 Claude 平台上不可用。
* **已开启使用额度**：您的账户必须开启使用额度，这允许超出计划包含的使用量进行计费。对于个人账户，请在您的 [Console 计费设置](https://platform.claude.com/settings/organization/billing)中开启。对于 Team 和 Enterprise 版本，管理员必须为组织开启使用额度。

  快速模式使用直接从使用额度中扣除，即使您的套餐中仍有剩余使用量。这意味着快速模式的token不计入套餐包含的使用量，并从第一个token开始就按快速模式费率计费。

* **团队和企业的管理员启用**：快速模式默认对团队和企业组织禁用。管理员必须[明确启用快速模式](#为您的组织启用快速模式)后，用户才能访问该功能。

  如果您的管理员未为您的组织启用快速模式，`/fast` 命令将显示"您的组织已禁用快速模式。"

### 为您的组织启用快速模式

管理员可在以下位置启用快速模式：

* **控制台**（API 客户端）：[Claude Code 偏好设置](https://platform.claude.com/claude-code/preferences)
* **Claude AI**（团队版和企业版）：[管理员设置 > Claude Code](https://claude.ai/admin-settings/claude-code)

另一个完全禁用快速模式的方法是设置 `CLAUDE_CODE_DISABLE_FAST_MODE=1`。请参阅[环境变量](/zh/env-vars)。

### 要求每个会话单独选择启用

默认情况下，快速模式在多个会话间持续生效：如果用户启用了快速模式，该状态将在后续会话中保持。使用[团队版](https://claude.com/pricing?utm_source=claude_code&utm_medium=docs&utm_content=fast_mode_teams#team-&-enterprise)或[企业版](https://anthropic.com/contact-sales?utm_source=claude_code&utm_medium=docs&utm_content=fast_mode_enterprise)计划的管理员可以通过在[托管设置](/zh/settings#settings-files)或[服务器托管设置](/zh/server-managed-settings)中将 `fastModePerSessionOptIn` 设置为 `true` 来阻止这种情况。这将导致每个会话开始时快速模式处于关闭状态，要求用户使用 `/fast` 命令明确启用它。
```json
{
  "fastModePerSessionOptIn": true
}
```
此功能适用于用户运行多个并发会话的组织，有助于控制成本。用户仍可在需要时通过 `/fast` 启用快速模式，但该设置会在每个新会话开始时重置。用户的快速模式偏好设置仍会被保留，因此移除此设置将恢复默认的持久行为。

## 处理速率限制

快速模式与标准 Opus 有独立的速率限制池。Opus 4.8、Opus 4.7 和 Opus 4.6 的快速模式共享同一速率限制池：在其中任何一个上的使用量都会从相同的配额中扣除。当您触发快速模式速率限制或用尽使用额度时：

1.  快速模式会自动回退到标准速度
2.  `↯` 图标会变为灰色以表示进入冷却期
3.  您将以标准速度和定价继续工作
4.  冷却期结束后，快速模式会自动重新启用

若不想等待冷却期，可再次运行 `/fast` 手动禁用快速模式。
