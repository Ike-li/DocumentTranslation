# 按计划运行提示词

> 使用 /loop 和定时调度工具在 Claude Code 会话中重复运行提示词、轮询状态或设置一次性提醒。

定时任务需要 Claude Code v2.1.72 或更高版本。使用 `claude --version` 检查你的版本。

定时任务让 Claude 按间隔自动重新运行提示词。可用于轮询部署状态、关注 PR、检查长时间运行的构建，或在会话中提醒自己稍后做某事。如果需要在事件发生时立即响应而非轮询，请参阅[频道](/zh/channels)：你的 CI 可以直接将失败信息推送到会话中。如果需要让会话在满足条件之前持续工作而非按间隔执行，请参阅 [`/goal`](/zh/goal)。

任务是会话级的：它们存在于当前对话中，当你开始新对话时会停止。使用 `--resume` 或 `--continue` 恢复会话时，任何未[过期](#七天过期)的任务都会被恢复：在最近 7 天内创建的循环任务，或计划时间尚未到达的一次性任务。如需独立于任何会话持久存在的调度，请使用[例程](/zh/routines)在 Anthropic 托管基础设施上创建例程，设置[桌面定时任务](/zh/desktop-scheduled-tasks)，或使用 [GitHub Actions](/zh/github-actions)。

## 调度选项比较

Claude Code 提供三种调度循环或一次性工作的方式：

|                            | [云端](/zh/routines)          | [桌面](/zh/desktop-scheduled-tasks) | [`/loop`](/zh/scheduled-tasks)      |
| :------------------------- | :----------------------------- | :------------------------------------- | :---------------------------------- |
| 运行位置                    | Anthropic 云端                | 你的本地机器                           | 你的本地机器                        |
| 需要机器开机        | 否                             | 是                                    | 是                                 |
| 需要打开会话      | 否                             | 否                                     | 是                                 |
| 重启后持久化 | 是                            | 是                                    | 未过期时通过 `--resume` 恢复 |
| 访问本地文件      | 否（全新克隆）               | 是                                    | 是                                 |
| MCP 服务器                | 按任务配置的连接器 | [配置文件](/zh/mcp)和连接器 | 继承自会话               |
| 权限提示         | 否（自主运行）         | 按任务可配置                  | 继承自会话               |
| 可自定义调度      | 通过 CLI 中的 `/schedule`     | 是                                    | 是                                 |
| 最小间隔           | 1 小时                         | 1 分钟                               | 1 分钟                            |

对于需要在你的机器未开机时可靠运行的工作，使用**云端任务**。需要访问本地文件和工具时，使用**桌面任务**。在会话中快速轮询时，使用 **`/loop`**。

## 使用 /loop 重复运行提示词

`/loop`[内置技能](/zh/commands)是在会话保持打开期间重复运行提示词的最快方式。间隔和提示词都是可选的，你提供的内容决定了循环的行为。

| 你提供的内容          | 示例                     | 发生的情况                                                                                                  |
| :------------------------ | :-------------------------- | :------------------------------------------------------------------------------------------------------------ |
| 间隔和提示词       | `/loop 5m check the deploy` | 你的提示词按[固定间隔](#按固定间隔运行)运行                                              |
| 仅提示词               | `/loop check the deploy`    | 你的提示词在每次迭代时按 [Claude 选择的间隔](#让-claude-选择间隔)运行              |
| 仅间隔，或都不提供 | `/loop`                     | 运行[内置维护提示词](#运行内置维护提示词)，或运行你的 `loop.md`（如果存在） |

你也可以将另一个命令作为提示词传递，例如 `/loop 20m /review-pr 1234`，以在每次迭代时重新运行打包的工作流。

### 按固定间隔运行

当你提供间隔时，Claude 将其转换为 cron 表达式，调度任务，并确认节奏和任务 ID。

```text
/loop 5m check if the deployment finished and tell me what happened
```

间隔可以作为前置标记如 `30m` 引导提示词，或作为后置短语如 `every 2 hours` 跟随提示词。支持的单位有：`s` 表示秒，`m` 表示分钟，`h` 表示小时，`d` 表示天。

秒会向上取整到最近的分钟，因为 cron 的粒度为一分钟。不能映射到整数 cron 步长的间隔，如 `7m` 或 `90m`，会四舍五入到最近的有效间隔，Claude 会告诉你它选择了什么。

### 让 Claude 选择间隔

当你省略间隔时，Claude 会动态选择间隔而非按固定 cron 调度运行。每次迭代后，它会根据观察到的情况选择 1 分钟到 1 小时之间的延迟：构建正在完成或 PR 活跃时等待较短，没有待处理事项时等待较长。选择的延迟及其原因会在每次迭代结束时打印。

以下示例检查 CI 和评审评论，当 PR 趋于安静时 Claude 会在迭代之间等待更长时间：

```text
/loop check whether CI passed and address any review comments
```

当你请求动态 `/loop` 调度时，Claude 可能会直接使用[监控工具](/zh/tools-reference#monitor-tool)。监控工具运行后台脚本并将每行输出流式传回，这完全避免了轮询，通常比按间隔重新运行提示词更节省 token 且响应更快。

动态调度的循环会像其他任务一样出现在你的[定时任务列表](#管理定时任务)中，因此你可以用相同的方式列出或取消它。[抖动规则](#抖动)不适用于它，但[七天过期](#七天过期)适用：循环会在你启动七天后自动结束。

在 Bedrock、Vertex AI 和 Microsoft Foundry 上，没有间隔的提示词会按固定的 10 分钟间隔运行。

### 运行内置维护提示词

当你省略提示词时，Claude 会使用内置维护提示词而非你提供的提示词。每次迭代时，它会按顺序完成以下工作：

* 继续对话中任何未完成的工作
* 处理当前分支的拉取请求：评审评论、失败的 CI 运行、合并冲突
* 当没有其他待处理事项时，运行清理工作，如 bug 搜索或代码简化

Claude 不会在该范围之外启动新的行动，且不可逆的操作（如推送或删除）仅在继续对话中已授权的操作时才会执行。

```text
/loop
```

单独的 `/loop` 会按[动态选择的间隔](#让-claude-选择间隔)运行此提示词。添加间隔，例如 `/loop 15m`，可改为按固定调度运行。要用你自己的默认提示词替换内置提示词，请参阅[使用 loop.md 自定义默认提示词](#使用-loopmd-自定义默认提示词)。

在 Bedrock、Vertex AI 和 Microsoft Foundry 上，不带提示词的 `/loop` 会打印使用说明而非运行维护提示词。

### 使用 loop.md 自定义默认提示词

`loop.md` 文件用你自己的指令替换内置维护提示词。它为单独的 `/loop` 定义单个默认提示词，而非多个独立定时任务的列表，且在命令行提供提示词时会被忽略。要在此基础上调度额外的提示词，请使用 `/loop <提示词>` 或[直接询问 Claude](#管理定时任务)。

Claude 会在两个位置查找该文件，并使用找到的第一个。

| 路径                | 范围                                                            |
| :------------------ | :--------------------------------------------------------------- |
| `.claude/loop.md`   | 项目级。当两个文件都存在时优先。           |
| `~/.claude/loop.md` | 用户级。适用于任何未定义自己文件的项目。 |

该文件是纯 Markdown，没有必需的结构。就像你直接输入 `/loop` 提示词一样编写它。以下示例保持发布分支健康：

```markdown title=".claude/loop.md"
Check the `release/next` PR. If CI is red, pull the failing job log,
diagnose, and push a minimal fix. If new review comments have arrived,
address each one and resolve the thread. If everything is green and
quiet, say so in one line.
```

对 `loop.md` 的编辑会在下次迭代时生效，因此你可以在循环运行时优化指令。当两个位置都没有 `loop.md` 时，循环会回退到内置维护提示词。保持文件简洁：超过 25,000 字节的内容会被截断。

在 Bedrock、Vertex AI 和 Microsoft Foundry 上，不会读取 `loop.md`，不带提示词的 `/loop` 会打印使用说明。

### 停止循环

要在循环等待下一次迭代时停止 `/loop`，按 `Esc`。这会清除待处理的唤醒，使循环不再触发。通过[直接询问 Claude](#管理定时任务) 调度的任务不受 `Esc` 影响，会一直保留直到你删除它们。

在[自定步调模式](#让-claude-选择间隔)下，当任务可证明完成时，Claude 也可以通过不调度下一次唤醒来自行结束循环。固定间隔的循环会持续运行，直到你停止它们或[七天到期](#七天过期)。

## 设置一次性提醒

对于一次性提醒，用自然语言描述你想要的内容，而非使用 `/loop`。Claude 会调度一个运行后自动删除的单次任务。

```text
remind me at 3pm to push the release branch
```

```text
in 45 minutes, check whether the integration tests passed
```

Claude 使用 cron 表达式将触发时间固定到具体的分钟和小时，并确认何时触发。

## 管理定时任务

用自然语言询问 Claude 列出或取消任务，或直接引用底层工具。

```text
what scheduled tasks do I have?
```

```text
cancel the deploy check job
```

底层实现中，Claude 使用以下工具：

| 工具         | 用途                                                                                                         |
| :----------- | :-------------------------------------------------------------------------------------------------------------- |
| `CronCreate` | 调度新任务。接受 5 字段 cron 表达式、要运行的提示词，以及是循环触发还是单次触发。 |
| `CronList`   | 列出所有定时任务及其 ID、调度和提示词。                                                |
| `CronDelete` | 按 ID 取消任务。                                                                                            |

每个定时任务都有一个 8 字符的 ID，可传递给 `CronDelete`。一个会话最多可同时持有 50 个定时任务。

## 定时任务如何运行

调度器每秒检查一次到期的任务，并以低优先级入队。定时提示词在你的轮次之间触发，而非在 Claude 响应过程中。如果 Claude 在任务到期时正忙，提示词会等到当前轮次结束。

所有时间按你的本地时区解释。像 `0 9 * * *` 这样的 cron 表达式表示你运行 Claude Code 所在时区的上午 9 点，而非 UTC。

### 抖动

为避免所有会话在同一时刻同时请求 API，调度器会为触发时间添加确定性偏移：

* 循环任务在计划时间后最多 30 分钟触发（对于运行频率高于每小时的任务，最多为间隔的一半）。计划在 `:00` 的每小时任务可能在 `:30` 之前的任何时刻触发。
* 计划在整点或半点的一次性任务最多提前 90 秒触发。

偏移量由任务 ID 推导，因此同一任务总是获得相同的偏移。如果精确计时很重要，选择不是 `:00` 或 `:30` 的分钟，例如 `3 9 * * *` 而非 `0 9 * * *`，这样一次性抖动就不会生效。

### 七天过期

循环任务在创建 7 天后自动过期。任务会最后一次触发，然后自行删除。这限制了被遗忘的循环可以运行的时长。如果需要循环任务持续更长时间，请在到期前取消并重新创建，或使用[例程](/zh/routines)或[桌面定时任务](/zh/desktop-scheduled-tasks)进行持久调度。

## Cron 表达式参考

`CronCreate` 接受标准 5 字段 cron 表达式：`分钟 小时 日 月 星期`。所有字段支持通配符（`*`）、单个值（`5`）、步长（`*/15`）、范围（`1-5`）和逗号分隔列表（`1,15,30`）。

| 示例        | 含义                      |
| :------------- | :--------------------------- |
| `*/5 * * * *`  | 每 5 分钟              |
| `0 * * * *`    | 每小时整点       |
| `7 * * * *`    | 每小时第 7 分钟 |
| `0 9 * * *`    | 每天本地时间上午 9 点       |
| `0 9 * * 1-5`  | 工作日本地时间上午 9 点        |
| `30 14 15 3 *` | 3 月 15 日本地时间下午 2:30     |

星期使用 `0` 或 `7` 表示周日，到 `6` 表示周六。不支持扩展语法如 `L`、`W`、`?` 和名称别名如 `MON` 或 `JAN`。

当日期和星期同时受限时，只要任一字段匹配即认为日期匹配。这遵循标准 vixie-cron 语义。

## 禁用定时任务

在环境中设置 `CLAUDE_CODE_DISABLE_CRON=1` 可完全禁用调度器。cron 工具和 `/loop` 将不可用，任何已调度的任务将停止触发。参见[环境变量](/zh/env-vars)获取完整的禁用标志列表。

## 限制

会话级调度有固有的约束：

* 任务仅在 Claude Code 运行且空闲时触发。关闭终端或让会话退出会停止触发。
* 错过的触发不会补发。如果任务的计划时间在 Claude 处于长时间运行请求时过去，它会在 Claude 变为空闲时触发一次，而非每个错过的间隔触发一次。
* 开始新对话会清除所有会话级任务。使用 `claude --resume` 或 `claude --continue` 恢复会话时，未过期的任务会被恢复：创建七天内的循环任务，以及计划时间尚未到达的一次性任务。后台 Bash 和监控任务在恢复时永远不会被恢复。

* [GitHub Actions](/zh/github-actions)：在 CI 中使用 `schedule` 触发器
