# 全屏渲染

> 启用更流畅、无闪烁的渲染模式，在长对话中支持鼠标操作并保持稳定的内存使用。

  全屏渲染是一项可选的[研究预览](#研究预览)功能，需 Claude Code v2.1.89 或更高版本。在当前对话中运行 `/tui fullscreen` 即可切换，或在低于 v2.1.110 的版本中设置 `CLAUDE_CODE_NO_FLICKER=1`。该功能的行为可能会根据反馈进行调整。

全屏渲染是 Claude Code CLI 的一种替代渲染路径，它能消除闪烁，在长对话中保持内存使用平稳，并增加鼠标支持。它在终端的备用屏幕缓冲区上绘制界面（类似 `vim` 或 `htop`），并且只渲染当前可见的消息。这减少了每次更新时发送到终端的数据量。

这种差异在渲染吞吐量成为瓶颈的终端模拟器中最为明显，例如 VS Code 集成终端、tmux 和 iTerm2。如果你的终端在 Claude 工作时滚动位置跳到顶部，或者屏幕在工具输出流式传入时闪烁，此模式可以解决这些问题。

  "全屏"这个术语描述的是Claude Code接管终端绘图区的方式，就像 `vim` 那样。它与最大化终端窗口无关，并且在任何窗口大小下都能工作。

## 启用全屏渲染

在任意 Claude Code 对话中运行 `/tui fullscreen`。命令行界面会保存 [`tui` 设置](/zh/settings#available-settings) 并在保持对话上下文不变的情况下重新启动进入全屏模式，因此你可以在会话中途切换而无需担心上下文丢失。不带参数运行 `/tui` 可以查看当前激活的渲染器。

你也可以在启动 Claude Code 前设置 `CLAUDE_CODE_NO_FLICKER` 环境变量：
```bash
CLAUDE_CODE_NO_FLICKER=1 claude
```
`tui` 设置与环境变量是等效的。`/tui` 命令会从重新启动的进程中清除 `CLAUDE_CODE_NO_FLICKER`，以便其写入的设置生效。

## 变化内容

全屏渲染改变了 CLI 绘制到终端的方式。输入框固定在屏幕底部，而不是随着输出流的推进而移动。如果输入框在 Claude 工作时保持静止，则全屏渲染处于活动状态。只有可见的消息保留在渲染树中，因此无论对话长度如何，内存占用保持恒定。

由于对话存在于备用屏幕缓冲区而不是终端的回滚缓冲区中，因此有些操作有所不同：

| 以前                                                    | 现在                                                                              | 详情                                                                       |
| :------------------------------------------------------ | :------------------------------------------------------------------------------- | :------------------------------------------------------------------------- |
| 使用 `Cmd+f` 或 tmux 搜索查找文本                       | `Ctrl+o` 进入转录模式，然后 `/` 搜索或 `[` 写入回滚缓冲区                          | [搜索和查看对话]                                             |
| 使用终端原生的点击拖动来选择和复制                        | 应用内选择，松开鼠标时自动复制                                                     | [使用鼠标](#使用鼠标)                                                       |
| `Cmd`-点击打开 URL                                      | 点击 URL                                                                          | [使用鼠标](#使用鼠标)                                                       |

如果鼠标捕获干扰了您的工作流程，您可以[将其关闭](#保留原生文本选择)同时保持无闪烁渲染。

## 使用鼠标

全屏渲染捕获鼠标事件并在 Claude Code 内部处理它们：

* **在提示输入框中点击**，将光标定位到您正在输入的文本中的任意位置。
* **在 `/` 命令或 `@` 文件列表中点击建议**，接受该建议。悬停会高亮显示光标下的行。
* **点击折叠的工具结果**，展开并查看完整输出。再次点击可折叠。工具调用及其结果会一起展开。只有具有更多内容可显示的消息才可点击。
* **点击 URL 或文件路径**打开它。工具输出中的文件路径（例如在 Edit 或 Write 之后打印的路径）会在您的默认应用程序中打开。普通的 `http://` 和 `https://` URL 会在您的浏览器中打开。在大多数终端中，这会取代原生的 `Cmd`-点击或 `Ctrl`-点击，鼠标捕获会拦截这些操作。在 VS Code 集成终端和类似的基于 xterm.js 的终端中，请继续使用 `Cmd`-点击。Claude Code 会将控制权交还给终端自身的链接处理程序，以避免链接被打开两次。
* **点击并拖动**以选择对话中的任何文本。双击选择一个单词，匹配 iTerm2 的单词边界，因此文件路径会作为一个整体被选中。三击选择整行。
* **使用鼠标滚轮滚动**以浏览对话。

所选文本会在松开鼠标时自动复制到剪贴板。要关闭此功能，请在 `/config` 中切换“选择时复制”选项。关闭后，按 `Ctrl+Shift+c` 手动复制。在支持 kitty 键盘协议的终端（如 kitty、WezTerm、Ghostty 和 iTerm2）上，`Cmd+c` 也可以使用。如果您有一个活动的选择区域，`Ctrl+c` 会复制而不是取消操作。

当有活动的选择区域时，按住 `Shift` 并使用箭头键从键盘扩展选择范围。当选择到达顶部或底部边缘时，`Shift+↑` 和 `Shift+↓` 会滚动视口。`Shift+Home` 和 `Shift+End` 扩展选择到当前行的开头或结尾。

## 滚动对话

全屏渲染在应用内部处理滚动。使用这些快捷键导航：

| 快捷键          | 操作                                               |
| :-------------- | :------------------------------------------------- |
| `PgUp` / `PgDn` | 向上或向下滚动半屏                                 |
| `Ctrl+Home`     | 跳转到对话开头                                     |
| `Ctrl+End`      | 跳转到最新消息并重新启用自动跟随                     |
| 鼠标滚轮        | 一次滚动几行                                       |

在没有专用 `PgUp`、`PgDn`、`Home` 或 `End` 键的键盘上（如 MacBook 键盘），请按住 `Fn` 键并配合方向键：`Fn+↑` 发送 `PgUp`，`Fn+↓` 发送 `PgDn`，`Fn+←` 发送 `Home`，`Fn+→` 发送 `End`。这样 `Ctrl+Fn+→` 就成了跳转到底部的快捷键。如果这感觉不方便，可以使用鼠标滚轮滚动到底部以恢复跟随，或者将 `scroll:bottom` 重新绑定到一个更易按到的键。

这些操作可以重新绑定。完整的操作名称列表（包括没有默认绑定的半页和全页变体）请参见[滚动操作](/zh/keybindings#scroll-actions)。

### 自动跟随

向上滚动会暂停自动跟随，这样新输出就不会将您拉回底部。按 `Ctrl+End` 或滚动到底部以恢复跟随。

要完全关闭自动跟随，使视图停留在您离开的位置，请打开 `/config` 并将“自动滚动”设置为关闭。禁用自动滚动后，视图永远不会自行跳转到底部。需要响应的权限提示和其他对话框仍然会滚动到视图中，不受此设置影响。

### 鼠标滚轮滚动

鼠标滚轮滚动需要您的终端将鼠标事件转发给 Claude Code。大多数终端在应用程序请求时都会这样做。iTerm2 将其设置为每个配置文件独立的选项：如果滚轮没有反应但 `PgUp` 和 `PgDn` 有效，请打开 设置 → 配置文件 → 终端 并启用“启用鼠标报告”。点击展开和文本选择功能也需要相同的设置。

如果鼠标滚轮滚动感觉缓慢，您的终端可能在每个物理刻度上只发送一个滚动事件，没有倍数。一些终端（如 Ghostty 和启用了更快滚动的 iTerm2）已经放大了滚轮事件。其他终端（包括 VS Code 集成终端）每个刻度只发送一个事件。Claude Code 无法检测是哪种情况。

设置 `CLAUDE_CODE_SCROLL_SPEED` 以乘以基本滚动距离：
```bash
export CLAUDE_CODE_SCROLL_SPEED=3
```
数值 `3` 匹配 `vim` 及类似应用程序中的默认设置。该设置接受 1 到 20 之间的值。

要交互式地调整滚动速度，请运行 `/scroll-speed`。对话框中显示一个标尺，您可以在打开状态下滚动标尺，以便立即感受变化。按 `←` 和 `→` 进行调整，按 `r` 重置为自动检测的默认值，按 `Enter` 保存。该命令会写入与 `CLAUDE_CODE_SCROLL_SPEED` 环境变量相同的值，并持久化到 `~/.claude/settings.json`。该命令在 JetBrains IDE 终端中不可用。

### 在 JetBrains IDE 终端中滚动

在 JetBrains IDE 终端中，Claude Code 使用其自身的滚动处理方式并忽略 `CLAUDE_CODE_SCROLL_SPEED`。该终端发送滚动事件的速率远高于其他模拟器，因此在其他地方调整合适的乘数在此处会过冲。

在 2025.2 版本中，该终端还存在一些滚动轮错误，会产生虚假的箭头键事件和方向错误的事件。Claude Code 在运行时检测这些错误并自动进行缓解，因此触控板和鼠标滚轮滚动无需配置即可正常工作。要获得最佳滚动体验，请升级到 2025.3 或更高版本。如果检测到错误，Claude Code 会在您首次滚动时显示提示。

## 搜索和查看会话

`Ctrl+o` 在普通提示词模式和转录模式之间切换。要获得更简洁的视图（仅显示您最后一次的提示词、工具调用的单行摘要（带编辑差异统计）以及最终响应），请运行 `/focus`。该设置在会话间保持不变。再次运行 `/focus` 可将其关闭。

转录模式增加了类似 `less` 的导航和搜索功能：

| 按键                                | 操作                                                                                                     |
| :---------------------------------- | :------------------------------------------------------------------------------------------------------- |
| `/`                                 | 打开搜索。输入以查找匹配项，`Enter` 接受，`Esc` 取消并恢复您的滚动位置                                   |
| `n` / `N`                           | 跳转到下一个或上一个匹配项。关闭搜索栏后仍有效                                                           |
| `j` / `k` 或 `↑` / `↓`             | 滚动一行                                                                                                 |
| `g` / `G` 或 `Home` / `End`        | 跳转到顶部或底部                                                                                         |
| `Ctrl+u` / `Ctrl+d`                 | 滚动半页                                                                                                 |
| `Ctrl+b` / `Ctrl+f` 或 `Space` / `b` | 滚动整页                                                                                                 |
| `Ctrl+o`、`Esc` 或 `q`              | 退出转录模式并返回到提示词                                                                               |

您的终端的 `Cmd+f` 和 tmux 搜索无法看到对话内容，因为它位于备用屏幕缓冲区，而非原生回滚缓冲区中。要将内容交还给您的终端，请先按 `Ctrl+o` 进入转录模式，然后：

* **`[`**：将完整对话（包含所有工具输出）写入您终端的原生回滚缓冲区。对话现在成为您终端中的普通文本，因此 `Cmd+f`、tmux 复制模式以及任何其他原生工具都可以对其进行搜索或选择。较长的会话在此过程中可能会暂停片刻。这将持续到您使用 `Esc` 或 `q` 退出转录模式（这将使您返回到全屏渲染）为止。下一次 `Ctrl+o` 将重新开始。
* **`v`**：将对话写入一个临时文件，并在 `$VISUAL` 或 `$EDITOR` 中打开它。

按 `Esc` 或 `q` 返回到提示词。

## 清除会话

在两秒内按两次 `Ctrl+L` 可运行 `/clear` 并开始新的会话。第一次按键会重绘屏幕并显示提示；第二次按键会清除会话。在 macOS 上，双击 `Cmd+K` 也会运行 `/clear`。

## 与 tmux 一起使用

全屏渲染在 tmux 内部可以工作，但有三个注意事项。

鼠标滚轮滚动需要 tmux 的鼠标模式。如果您的 `~/.tmux.conf` 尚未启用它，请添加以下行并重新加载配置：
```bash
set -g mouse on
```
如果不开启鼠标模式，滚轮事件会发送给 tmux 而非 Claude Code。键盘滚动（使用 `PgUp` 和 `PgDn`）则始终有效。若 Claude Code 启动时检测到 tmux 未开启鼠标模式，会显示一次性提示。

全屏渲染与 iTerm2 的 tmux 集成模式不兼容，该模式通过 `tmux -CC` 进入。在此集成模式下，iTerm2 将每个 tmux 窗格渲染为原生分割面板，而非让 tmux 绘制终端。此时备用屏幕缓冲区和鼠标追踪功能无法正常工作：鼠标滚轮无效，双击可能损坏终端状态。请勿在 `tmux -CC` 会话中启用全屏渲染。在 iTerm2 内使用常规 tmux（不带 `-CC`）则运作正常。

tmux 不支持同步输出，因此重绘时可能出现比直接在终端运行 Claude Code 更多的闪烁。若闪烁明显（尤其在 SSH 环境下），请在 tmux 外开启独立终端标签页运行 Claude Code。

## 保留原生文本选择

鼠标捕获是最常见的冲突点，尤其在 SSH 或 tmux 环境中。当 Claude Code 捕获鼠标事件时，终端的原生选中即复制功能将失效。通过点击拖拽创建的选择仅存在于 Claude Code 内部，不会进入终端选择缓冲区，因此 tmux 复制模式、Kitty 提示符等工具无法识别该选择。

Claude Code 会尝试将选择内容写入剪贴板，但具体路径取决于您的配置：在 tmux 内写入 tmux 粘贴缓冲区；通过 SSH 时回退至 OSC 52 转义序列（部分终端默认禁用此功能）。iTerm2 需开启“设置 → 通用 → 选择 → 终端应用程序可访问剪贴板”后才允许此操作。在 iTerm2 中运行 [`/terminal-setup`](/zh/terminal-config) 可自动启用该设置。每次复制后 Claude Code 会弹出提示，说明写入路径。

如需临时使用原生选择，按住终端的绕过修饰键（iTerm2 中为 `Option`，多数 Linux 和 Windows 终端中为 `Shift`）后点击拖拽。此修饰键会让终端自行处理选择操作，而非将鼠标事件转发给 Claude Code，之后 `Cmd+C` 及终端其他复制快捷键均可正常使用。

若需始终依赖原生选择，可设置 `CLAUDE_CODE_DISABLE_MOUSE=1` 以禁用鼠标捕获，同时保留无闪烁渲染和扁平内存架构：
```bash
CLAUDE_CODE_NO_FLICKER=1 CLAUDE_CODE_DISABLE_MOUSE=1 claude
```
鼠标捕获被禁用时，键盘滚动操作如 `PgUp`、`PgDn`、`Ctrl+Home` 和 `Ctrl+End` 仍然有效，并且您的终端会以原生方式处理选择操作。您将失去在 Claude Code 内部单击定位光标、单击展开工具输出、单击 URL 和滚轮滚动的功能。

## 研究预览

全屏渲染是一项研究预览功能。它已在常见的终端模拟器上经过测试，但在不太常见的终端或特殊配置下可能会遇到渲染问题。

如果遇到问题，请在 Claude Code 内部运行 `/feedback` 进行报告，或在 [claude-code GitHub 仓库](https://github.com/anthropics/claude-code/issues) 上提交问题。请包含您的终端模拟器名称和版本。

要关闭全屏渲染，请运行 `/tui default`，或者如果您通过该方式启用了它，请取消设置 `CLAUDE_CODE_NO_FLICKER` 环境变量。要强制使用经典渲染器（无论保存的 `tui` 设置如何），请设置 `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1`。经典渲染器会将对话保留在您终端的原生回滚历史中，因此 `Cmd+f` 和 tmux 复制模式将照常工作。
