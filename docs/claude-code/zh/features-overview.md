# 扩展 Claude Code

> 了解何时使用 CLAUDE.md、技能、子代理、钩子、MCP 和插件。

Claude Code 将一个能推理代码的模型与用于文件操作、搜索、执行和网页访问的[内置工具](/zh/how-claude-code-works#tools)相结合。内置工具涵盖大多数编码任务。本指南涵盖扩展层：用于添加自定义功能以控制 Claude 的认知内容、连接外部服务和自动化工作流。

  关于核心智能体循环的工作原理，请参阅 [Claude Code 工作原理](/zh/how-claude-code-works)。

**刚接触 Claude Code？** 请先阅读 [CLAUDE.md](/zh/memory) 了解项目约定，然后根据[具体触发场景](#逐步构建你的设置)添加其他扩展。

## 概览

扩展可接入智能体循环的不同环节：

* **[CLAUDE.md](/zh/memory)** 为 Claude 在每次会话中添加持久上下文
* **[技能](/zh/skills)** 添加可复用的知识和可调用的工作流
* **[代码智能](/zh/tools-reference#lsp-tool-behavior)** 将 Claude 连接到语言服务器，实现符号级导航和实时类型错误提示
* **[MCP](/zh/mcp)** 将 Claude 连接到外部服务和工具
* **[子代理](/zh/sub-agents)** 在隔离的上下文中运行自己的循环，并返回摘要
* **[智能体团队](/zh/agent-teams)** 协调多个独立会话，共享任务并支持点对点通信
* **[钩子](/zh/hooks-guide)** 在生命周期事件上触发，可运行脚本、发出 HTTP 请求、执行提示词或启动子代理
* **[插件](/zh/plugins)** 和 **[市场](/zh/plugin-marketplaces)** 对这些功能进行打包和分发

[技能](/zh/skills) 是最灵活的扩展。技能是一个 Markdown 文件，包含知识、工作流或指令。你可以通过 `/deploy` 等命令调用技能，Claude 也可以在相关时自动加载它们。技能可以在当前对话中运行，也可以通过子代理在隔离上下文中执行。

## 根据目标匹配功能

功能涵盖的范围很广：从 Claude 每次会话都能看到的常驻上下文，到你或 Claude 可以按需调用的能力，再到特定事件触发的后台自动化。下表列出了可用功能及其适用场景。

| 功能                                                        | 作用                                                  | 适用时机                                                                  | 示例                                                                         |
| -------------------------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| **CLAUDE.md**                                                  | 每次对话加载的持久上下文                  | 项目约定、“始终执行 X” 规则                                        | “使用 pnpm 而非 npm。提交前运行测试。”                               |
| **技能**                                                      | Claude 可使用的指令、知识和工作流         | 可复用内容、参考文档、可重复的任务                              | `/deploy` 运行你的部署检查清单；包含端点模式的 API 文档技能 |
| **子代理**                                                   | 隔离的执行上下文，返回摘要结果    | 上下文隔离、并行任务、专业工作者                          | 读取多个文件但只返回关键发现的研究任务               |
| **[智能体团队](/zh/agent-teams)**                             | 协调多个独立的 Claude Code 会话          | 并行研究、新功能开发、用竞争性假设调试 | 同时生成审查者来检查安全性、性能和测试        |
| **[代码智能](/zh/tools-reference#lsp-tool-behavior)** | 语言服务器导航和诊断                    | 静态类型语言、大型代码库中 grep 速度慢或不精确                | 跳转到符号的定义，而不是读取整个文件                 |
| **MCP**                                                        | 连接到外部服务                                  | 需要外部数据或操作                                                        | 查询数据库、发布到 Slack、控制浏览器                           |
| **钩子**                                                       | 由事件触发的脚本、HTTP 请求、提示词或子代理 | 必须在每个匹配事件上运行的自动化                                | 每次文件编辑后运行 ESLint                                                |

**[插件](/zh/plugins)** 是封装层。一个插件将技能、钩子、子代理和 MCP 服务器打包成一个可安装的单元。插件技能具有命名空间（如 `/my-plugin:review`），因此多个插件可以共存。当你想跨多个仓库复用相同设置，或通过**[市场](/zh/plugin-marketplaces)**分发给他人时，请使用插件。

### 逐步构建你的设置

你无需一开始就配置所有功能。每个功能都有可识别的触发点，大多数团队会按以下大致顺序添加它们：

| 触发场景                                                                          | 添加                                                                                            |
| :------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------- |
| Claude 连续两次搞错某个约定或命令                                  | 将其添加到 [CLAUDE.md](/zh/memory)                                                              |
| 你反复输入相同的提示词来启动一个任务                                  | 将其保存为用户可调用的[技能](/zh/skills)                                                |
| 你第三次将相同的操作手册或多步骤流程粘贴到聊天中 | 将其捕获为[技能](/zh/skills)                                                            |
| 你反复从 Claude 无法访问的浏览器标签页复制数据                        | 将该系统连接为 [MCP 服务器](/zh/mcp)                                                |
| Claude 需要读取多个文件来查找符号的定义或使用位置                | 安装适用于你语言的[代码智能插件](/zh/discover-plugins#code-intelligence) |
| 一个次要任务用你不会再参考的输出淹没你的对话       | 通过[子代理](/zh/sub-agents)处理它                                                  |
| 你希望某件事无需询问就能每次发生                           | 编写一个[钩子](/zh/hooks-guide)                                                                |
| 第二个仓库需要相同的设置                                         | 将其打包为[插件](/zh/plugins)                                                          |

同样的触发点也告诉你何时更新已有功能。重复的错误或反复出现的审查意见，是需要编辑 CLAUDE.md 的情况，而不是在聊天中一次性纠正。你反复手动调整的工作流，是需要再次修订的技能。

### 比较相似功能

有些功能可能看起来很相似。以下是如何区分它们。


    技能和子代理解决不同的问题：

    * **技能**是可以加载到任何上下文中的可复用内容
    * **子代理**是独立于主会话运行的独立工作者

    | 方面                                            | 技能                                           | 子代理                                                             |
    | ----------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------- |
    | **它是什么**                                    | 可复用的指令、知识或工作流                    | 拥有独立上下文的独立工作者                                        |
    | **主要优势**                                    | 在多个上下文中共享内容                         | 上下文隔离。工作独立进行，仅返回摘要                              |
    | **[上下文窗口](/zh/context-window)影响**        | 增加到主窗口中                                 | 使用独立窗口，拥有自己的输入和输出 token                          |
    | **最适合**                                      | 参考资料、可调用的工作流                       | 需要读取大量文件的任务、并行工作、专业工作者                      |

    **技能可分为参考型和动作型。** 参考技能提供 Claude 在整个会话中使用的知识（例如你的 API 风格指南）。动作技能指示 Claude 执行特定操作（例如 `/deploy`，它会运行你的部署工作流）。

    当你需要上下文隔离，或者你的上下文窗口即将满时，**使用子代理**。子代理可能会读取数十个文件或执行大量搜索，但你的主会话仅接收摘要。由于子代理的工作不消耗主上下文，因此当您不需要保留中间工作可见性时，这也很有用。自定义子代理可以拥有自己的指令，并可以预加载技能。

    **它们可以结合使用。** 子代理可以预加载特定技能（`skills:` 字段）。技能可以使用 `context: fork` 在隔离的上下文中运行。详见[技能](/zh/skills)部分。



    两者都存储指令，但加载方式和用途各不相同。

    | 方面                    | CLAUDE.md                    | 技能                                   |
    | ------------------------- | ---------------------------- | --------------------------------------- |
    | **加载时机**                 | 每次会话自动加载 | 按需加载                               |
    | **能否包含文件**     | 能，通过 `@path` 导入    | 能，通过 `@path` 导入               |
    | **能否触发工作流** | 否                           | 能，通过 `/<name>`                     |
    | **最适用于**              | "始终执行X"规则          | 参考资料、可调用的工作流 |

    **将其放入 CLAUDE.md**，如果 Claude 应该始终知道它：编码规范、构建命令、项目结构、"绝不执行X"规则。

    **将其放入技能**，如果它是 Claude 有时需要参考的资料（API 文档、风格指南）或您通过 `/<name>` 触发的工作流（部署、审查、发布）。

    **经验法则：** 将 CLAUDE.md 保持在 200 行以内。如果它在增长，请将参考资料移至技能或拆分为 [`.claude/rules/`](/zh/memory#organize-rules-with-claude/rules/) 文件。



    三者都存储指令，但加载方式不同：

    | 方面         | CLAUDE.md                               | `.claude/rules/`                                   | 技能                                       |
    | ------------ | --------------------------------------- | -------------------------------------------------- | ---------------------------------------- |
    | **加载时机** | 每个会话                                | 每个会话，或当匹配的文件被打开时                   | 按需加载，在调用或相关时                   |
    | **作用范围** | 整个项目                                | 可限定于特定文件路径                               | 针对特定任务                               |
    | **最适用于** | 核心约定和构建命令                      | 特定语言或目录的准则                               | 参考资料、可重复的工作流                   |

    **将 CLAUDE.md 用于**每个会话都需要的指令：构建命令、测试约定、项目架构。

    **将规则用于**保持 CLAUDE.md 的聚焦。带有 [`paths` frontmatter](/zh/memory#path-specific-rules) 的规则仅在 Claude 处理匹配文件时加载，从而节省上下文。

    **将技能用于** Claude 仅有时需要的内容，比如 API 文档或你用 `/<name>` 触发的部署检查清单。



    两者都能实现并行工作，但架构上有所不同：

    * **子代理**在您的会话内运行，并将结果报告回主上下文
    * **代理团队**是相互独立的Claude Code会话，彼此之间可以进行通信

    | 方面              | 子代理                                           | 代理团队                                            |
    | ----------------- | ------------------------------------------------ | --------------------------------------------------- |
    | **上下文**        | 拥有独立的上下文窗口；结果返回给调用者           | 拥有独立的上下文窗口；完全独立                      |
    | **通信**          | 仅将结果报告给主代理                             | 团队成员之间可以直接互相发送消息                    |
    | **协调**          | 主代理管理所有工作                               | 共享任务列表并进行自我协调                          |
    | **最适用于**      | 只需结果的聚焦型任务                             | 需要讨论和协作的复杂工作                            |
    | **Token成本**     | 较低：结果汇总后返回主上下文                     | 较高：每个团队成员都是独立的Claude实例              |

    当您需要一个快速、专注的工作者时，**使用子代理**：研究一个问题、验证一个说法、审查一个文件。子代理完成工作并返回摘要。您的主对话保持整洁。

    当团队成员需要分享发现、互相质疑并独立协调时，**使用代理团队**。代理团队最适用于存在竞争假设的研究、并行代码审查，以及每位成员负责独立部分的新功能开发。

    **过渡点：** 如果您正在运行并行的子代理但遇到了上下文限制，或者您的子代理需要相互通信，那么代理团队就是自然的下一步选择。

      代理团队是实验性功能且默认禁用。有关设置和当前限制，请参阅[代理团队](/zh/agent-teams)。




    MCP 将 Claude 连接到外部服务。技能则扩展了 Claude 的知识库，包括如何有效地使用这些服务。

    | 方面           | MCP                                                          | 技能                                                         |
    | -------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
    | **是什么**     | 连接外部服务的协议                                           | 知识、工作流和参考资料                                       |
    | **提供什么**   | 工具和数据访问                                               | 知识、工作流、参考资料                                       |
    | **示例**       | Slack 集成、数据库查询、浏览器控制                           | 代码审查清单、部署工作流、API 风格指南                        |

    它们解决不同的问题，并能很好地协同工作：

    **MCP** 为 Claude 提供了针对外部系统的专用工具，连接和认证由服务器处理。

    **技能** 教会 Claude 如何有效地使用这些工具，以及你可以通过 `/<name>` 触发的工作流。一个技能可能包含你团队的数据库架构和查询模式，或者一个包含你团队消息格式规则的 `/post-to-slack` 工作流。

    示例：一个 MCP 服务器将 Claude 连接到你的数据库。一个技能则教会 Claude 你的数据模型、常见的查询模式，以及针对不同任务应使用哪些表。



    钩子在生命周期事件中触发；技能则被加载到上下文中供 Claude 运用。

    | 方面           | 钩子                                                                              | 技能                                                                 |
    | ---------------- | --------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
    | **运行方式**         | 执行 Shell 命令、发送 HTTP 请求、调用 LLM 提示词或启动子代理                            | Claude 阅读并遵循的指令                                 |
    | **触发条件** | [生命周期事件](/zh/hooks#hook-events)，如 `PostToolUse` 或 `SessionStart` | 您输入 `/<名称>`，或 Claude 将任务描述与技能匹配 |
    | **确定性**  | 总是在对应事件上触发；触发过程是确定的                              | Claude 解释指令；结果可能变化                  |
    | **上下文开销** | 除非钩子返回输出，否则开销为零                                               | 每次会话加载描述；使用时加载全部内容          |
    | **最佳应用场景**     | 编辑后代码检查、阻止不安全命令、记录日志、发送通知             | 需要推理、参考材料、多步骤任务的工作流   |

    **使用钩子**当操作必须每次都以相同方式执行，且无需 Claude 思考时。例如：保存时格式化代码、拒绝 `rm -rf /` 命令、会话结束时发送 Slack 消息。

    **使用技能**当 Claude 需要决定如何应用步骤，或当内容是知识而非脚本时。例如：`/release` 检查清单、您的 API 风格指南、调试手册。

    **在钩子中设置防护栏。** 在 CLAUDE.md 或技能中写入“永不编辑 `.env`”这类指令是请求，而非保证。而通过 `PreToolUse` 钩子阻止编辑操作才是强制执行。如果一条规则必须每次都成立，请将其设为钩子而非提示词指令。

    **钩子输出会进入上下文。** 运行代码检查工具的 `PostToolUse` 钩子会将结果作为 Claude 阅读的文本反馈回来；而 `/fix-lint` 技能则告诉 Claude 如何解决这些问题。


### 理解功能的分层机制

功能可以在多个层级定义：用户级、项目级、通过插件或通过托管策略。你还可以在子目录中嵌套 CLAUDE.md 文件，或将技能放在 monorepo 的特定包中。当同一功能存在于多个层级时，它们的分层规则如下：

* **CLAUDE.md 文件** 是累加式的：所有层级的内容会同时贡献给 Claude 的上下文。你工作目录及其上级目录的文件在启动时加载；子目录的文件会在你进入其中工作时加载。当指令发生冲突时，Claude 会运用判断力来协调，更具体的指令通常优先。参见 [CLAUDE.md 文件如何加载](/zh/memory#how-claude-md-files-load)。
* **技能和子代理** 按名称覆盖：当多个层级存在同名功能时，会根据优先级确定一个定义胜出（技能：托管 > 用户 > 项目；子代理：托管 > CLI 标志 > 项目 > 用户 > 插件）。插件技能使用[命名空间](/zh/plugins#add-skills-to-your-plugin)以避免冲突。参见[技能查找](/zh/skills#where-skills-live)和[子代理作用域](/zh/sub-agents#choose-the-subagent-scope)。
* **MCP 服务器** 按名称覆盖：本地 > 项目 > 用户。参见 [MCP 作用域](/zh/mcp#scope-hierarchy-and-precedence)。
* **钩子** 是合并式的：所有已注册的钩子都会为其匹配的事件触发，无论其来源。参见[钩子](/zh/hooks)。

### 组合功能

每个扩展解决不同的问题：CLAUDE.md 处理始终在线的上下文，技能处理按需的知识和工作流，MCP 处理外部连接，子代理处理隔离，钩子处理自动化。实际配置会根据你的工作流组合使用它们。

例如，你可能会使用 CLAUDE.md 来定义项目规范，使用技能来处理部署工作流，使用 MCP 连接数据库，并使用钩子在每次编辑后运行 lint 检查。每个功能处理它最擅长的部分。

| 模式                     | 工作原理                                                                           | 示例                                                                                              |
| ---------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **技能 + MCP**          | MCP 提供连接；技能教会 Claude 如何很好地使用它                                            | MCP 连接到你的数据库，技能则记录你的 schema 和查询模式                                                  |
| **技能 + 子代理**         | 技能会生成子代理来进行并行工作                                                                | `/audit` 技能启动安全、性能和风格子代理，它们在隔离的上下文中工作                                             |
| **CLAUDE.md + 技能**     | CLAUDE.md 持有始终在线的规则；技能持有按需加载的参考资料                                           | CLAUDE.md 写着“遵循我们的 API 规范”，技能则包含完整的 API 风格指南                                        |
| **钩子 + MCP**           | 钩子通过 MCP 触发外部操作                                                                | 编辑后钩子在 Claude 修改关键文件时发送 Slack 通知                                                       |

## 理解上下文成本

你添加的每项功能都会消耗 Claude 的一部分上下文。过多的内容可能会填满你的上下文窗口，但也可能增加噪音，使 Claude 效率降低；技能可能无法正确触发，或者 Claude 可能会忘记你的规范。理解这些权衡有助于构建高效的配置。要交互式地查看这些功能在运行的会话中如何组合，请参阅[探索上下文窗口](/zh/context-window)。

### 各功能的上下文成本

每项功能都有不同的加载策略和上下文成本：

| 功能                  | 加载时机                     | 加载内容                                              | 上下文成本                                  |
| --------------------- | ---------------------------- | --------------------------------------------------- | -------------------------------------------- |
| **CLAUDE.md**         | 会话启动                     | 完整内容                                              | 每个请求                                     |
| **技能**              | 会话启动 + 使用时            | 启动时加载描述，使用时加载完整内容                              | 低（描述在每个请求中加载）\*                        |
| **MCP 服务器**        | 会话启动                     | 工具名称；完整 schema 按需加载                            | 低，直到使用工具                               |
| **代码智能**          | 文件编辑后及按需             | 编辑后加载诊断；查找时加载符号位置                            | 低；减少其他地方的文件读取次数                       |
| **子代理**            | 生成时                       | 具有指定技能的全新上下文                                    | 与主会话隔离                                   |
| **钩子**              | 触发时                       | 无（在外部运行）                                        | 零，除非钩子返回额外的上下文                       |

\* 默认情况下，技能描述在会话启动时加载，以便 Claude 决定何时使用它们。在技能的 frontmatter 中设置 `disable-model-invocation: true` 可以完全对 Claude 隐藏它，直到你手动调用。这可以将你只手动触发的技能的上下文成本降至零。对于不是你编写的技能，可以在设置中配置 [`skillOverrides`](/zh/skills#override-skill-visibility-from-settings) 来达到同样的效果，而无需编辑其文件。

### 理解功能的加载方式

每项功能在你的会话中加载的时间点不同。下面的选项卡解释了每项功能何时加载以及哪些内容会进入上下文。

<img src="https://mintcdn.com/claude-code/6yTCYq1p37ZB8-CQ/images/context-loading.svg?fit=max&auto=format&n=6yTCYq1p37ZB8-CQ&q=85&s=5a58ce953a35a2412892015e2ad6cb67" alt="上下文加载：CLAUDE.md 在会话启动时加载并保持在每个请求中。MCP 工具名称在启动时加载，完整 schema 延迟到使用时加载。技能在启动时加载描述，调用时加载完整内容。子代理获得隔离的上下文。钩子在外部运行。" width="720" height="410" data-path="images/context-loading.svg" />


    **触发时机：** 会话启动

    **加载内容：** 所有 `CLAUDE.md` 文件（托管级、用户级和项目级）的完整内容。

    **继承机制：** Claude 会从你的工作目录向上读取直至根目录的 `CLAUDE.md` 文件，并在访问子目录时发现其中嵌套的文件。详见 [CLAUDE.md 文件如何加载](/zh/memory#how-claude-md-files-load)。




    技能是Claude工具箱中的额外功能。它们可以是参考资料（如API风格指南），也可以是你通过 `/<name>` 触发的可调用工作流（如 `/deploy`）。Claude Code包含[内置技能](/zh/commands)，例如 `/code-review`、`/batch` 和 `/debug`，开箱即用。你也可以创建自己的技能。Claude会在适当时使用技能，或者你可以直接调用某个技能。

    **何时加载：** 取决于技能的配置。默认情况下，描述在会话启动时加载，完整内容在使用时加载。对于仅限用户使用的技能（`disable-model-invocation: true`），直到你调用它们之前，不会加载任何内容。

    **加载内容：** 对于模型可调用技能，Claude在每个请求中都能看到名称和描述。当你通过 `/<name>` 调用技能或Claude自动加载它时，完整内容会加载到你的对话中。

    **Claude如何选择技能：** Claude会将你的任务与技能描述进行匹配，以决定哪些技能是相关的。如果描述模糊或重叠，Claude可能会加载错误的技能，或者错过一个本可以提供帮助的技能。要告诉Claude使用特定技能，请通过 `/<name>` 调用它。具有 `disable-model-invocation: true` 的技能在你调用之前对Claude是不可见的。

    **上下文成本：** 在使用前很低。仅限用户使用的技能在调用前成本为零。

    **在子代理中：** 技能在子代理中的工作方式不同。它们不是按需加载，而是列在子代理 `skills` 字段中的技能在启动时被完全预加载到其上下文中。子代理仍然可以通过技能工具发现并调用未列出的项目、用户和插件技能。




    **何时加载：** 会话启动时。

    **加载内容：** 来自已连接服务器的工具名称。完整的 JSON 模式将延迟加载，直到 Claude 需要特定工具时才加载。

    **上下文成本：** [工具搜索](/zh/mcp#scale-with-mcp-tool-search) 默认开启，因此空闲的 MCP 工具消耗的上下文极少。




    **何时触发：** 文件编辑后，以及当 Claude 浏览代码时按需触发。

    **加载内容：** 每次文件编辑后的类型错误和警告。当 Claude 查找符号时，加载其定义、引用和类型信息。

    **上下文成本：** 低。符号查找通常替代广泛的文件读取，因此总体上下文使用量可能减少。




    **触发时机：** 按需触发，当你或 Claude 为某任务创建一个子代理时。

    **加载内容：** 全新、隔离的上下文，包含：

    * 代理自身的系统提示词，而非完整的 Claude Code 系统提示词
    * 代理 `skills:` 字段中列出的所有技能的完整内容
    * CLAUDE.md 和 git status，但内置的 Explore 和 Plan 代理[省略两者](/zh/sub-agents#what-loads-at-startup)
    * 主代理在提示词中传入的任何上下文

    **上下文成本：** 与主会话隔离。子代理不会继承你的对话历史或已调用的技能。




    **触发时机：** 触发时激活。钩子会在特定的生命周期事件触发，例如工具执行、会话边界、提示词提交、权限请求和压缩。完整列表请参见[钩子](/zh/hooks)。

    **加载内容：** 默认不加载任何内容。钩子在主对话之外执行。

    **上下文开销：** 零，除非钩子返回的输出作为消息添加到您的对话中。
