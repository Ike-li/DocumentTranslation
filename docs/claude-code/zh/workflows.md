# 使用动态工作流大规模编排子代理

> 动态工作流通过 Claude 编写的脚本编排多个子代理，你可以重复运行。适用于代码库审计、大规模迁移和交叉验证的研究任务。

{/* plan-availability: feature=workflows plans=pro,max,team,enterprise providers=all */}

动态工作流目前处于研究预览阶段。需要 Claude Code v2.1.154 或更高版本，适用于所有付费计划，支持 Anthropic API、Amazon Bedrock、Google Cloud Vertex AI 和 Microsoft Foundry。在 Pro 计划中，可通过 `/config` 中的 Dynamic workflows 行开启。

动态工作流是一个 JavaScript 脚本，用于大规模编排[子代理](/zh/sub-agents)。Claude 会根据你描述的任务编写脚本，运行时在后台执行，同时你的会话保持响应。

当一个任务需要的代理数量超过单次对话所能协调的范围，或者你希望将编排过程固化为可阅读、可重复运行的脚本时，就应该使用工作流。示例包括：整个代码库的 bug 排查、500 个文件的迁移、需要交叉验证来源的研究问题，以及值得从多个独立角度起草方案再做决策的复杂计划。

本页涵盖以下内容：

* 判断[何时使用工作流](#何时使用工作流)而非子代理或技能
* [运行内置工作流](#运行内置工作流) `/deep-research`
* [让 Claude 编写工作流](#让-claude-编写工作流)并保存
* 了解[工作流如何运行](#工作流如何运行)以及[管理运行](#管理运行)

## 何时使用工作流

[子代理](/zh/sub-agents)、[技能](/zh/skills)和工作流都可以运行多步骤任务。区别在于谁掌握计划：

|                                 | 子代理                          | 技能                           | 工作流                              |
| :------------------------------ | :----------------------------- | :--------------------------- | :----------------------------------- |
| 它是什么                         | Claude 生成的工作者              | Claude 遵循的指令             | 运行时执行的脚本                     |
| 谁决定下一步运行什么              | Claude，逐轮决定                | Claude，遵循提示词            | 脚本                                |
| 中间结果存放在哪里                | Claude 的上下文窗口              | Claude 的上下文窗口           | 脚本变量                             |
| 什么可以重复                      | 工作者定义                      | 指令                          | 编排过程本身                         |
| 规模                              | 每轮几个委托任务                 | 与子代理相同                   | 每次运行数十到数百个代理             |
| 中断                              | 重启当前轮次                     | 重启当前轮次                   | 可在同一会话中恢复                   |

工作流将计划移入代码。使用子代理和技能时，Claude 是编排者：逐轮决定下一步生成什么，每个结果都进入 Claude 的上下文。工作流脚本自行持有循环、分支和中间结果，因此 Claude 的上下文只需容纳最终答案。

将计划移入代码还使工作流能够应用可重复的质量模式，而不仅仅是运行更多代理：它可以让独立的代理在报告结果之前相互对抗性审查，或者从多个角度起草方案并相互权衡，从而获得比单次执行更可靠的结果。

## 运行内置工作流

体验工作流最快的方式是运行 `/deep-research`，这是 Claude Code 内置的[工作流](#内置工作流)，用于从多个来源调查问题。你会看到代理在后台按阶段工作，而你的会话保持可用，最终得到一份报告而非逐轮对话记录。

1. **运行工作流**

   使用 `/deep-research` 加上你想调查的问题。它会从多个角度展开网络搜索，获取并交叉验证找到的来源，最后合成一份带引用的报告。

   ```text
   /deep-research What changed in the Node.js permission model between v20 and v22?
   ```

2. **允许工作流**

   Claude Code 会询问是否允许运行该工作流。选择 **Yes** 继续。具体提示取决于你的权限模式。各模式选项详见[在运行前审批计划](#在运行前审批计划)。

3. **查看进度**

   运行在后台启动。执行 `/workflows`，使用方向键选择运行，按 Enter 打开进度视图：

   ```text
   /workflows
   ```

   视图显示每个阶段的代理数量、token 总量和耗时。进入任意阶段可查看其代理及每个代理的发现。完整操作说明见[查看运行](#查看运行)。

   你也可以从输入框下方的任务面板查看：运行期间会显示一行进度摘要。按向下箭头聚焦，再按 Enter 展开。

4. **阅读报告**

   运行完成后，报告会进入你的会话。每个论断都附有来源引用，未通过交叉验证的论断已被过滤。

要为自己的任务运行工作流，可以[让 Claude 编写一个](#让-claude-编写工作流)，一旦运行达到预期效果，就可以将其[保存](#保存工作流以供复用)为自定义命令。

### 内置工作流

Claude Code 包含 `/deep-research` 作为内置工作流：

| 命令                        | 功能                                                                                                                                                                                                                                                                                                                |
| :-------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/deep-research <question>` | 从多个角度对问题展开网络搜索，获取并交叉验证来源，对每个论断投票，返回带引用的报告（未通过交叉验证的论断已过滤）。需要 [WebSearch 工具](/zh/tools-reference#websearch-tool-behavior)可用 |

你[保存的工作流](#保存工作流以供复用)同样会成为命令，与内置工作流一起出现在 `/` 自动补全中。

### 查看运行

工作流在后台运行，代理工作时会话保持可用。随时执行 `/workflows` 可列出正在运行和已完成的工作流，选择一个即可打开进度视图。

```text
/workflows
```

进度视图显示每个阶段的代理数量、token 总量和耗时。页脚列出各操作的按键：

| 按键           | 操作                                                                                              |
| :------------- | :-------------------------------------------------------------------------------------------------- |
| `↑` / `↓`      | 选择阶段或代理                                                                                      |
| `Enter` 或 `→` | 进入选中的阶段，再进入代理可查看其提示词、最近的工具调用和结果                                        |
| `Esc`          | 返回上一级                                                                                          |
| `j` / `k`      | 在代理详情中滚动（内容溢出时）                                                                       |
| `p`            | 暂停或恢复运行                                                                                      |
| `x`            | 停止选中的代理，或焦点在运行上时停止整个工作流                                                        |
| `r`            | 重新启动选中的正在运行的代理                                                                         |
| `s`            | 将运行的脚本[保存](#保存工作流以供复用)为命令                                                         |

## 让 Claude 编写工作流

你可以通过两种方式让 Claude 为你的任务编写工作流：

* 在提示词中[请求工作流](#在提示词中请求工作流)，包含 `workflow` 关键词，Claude 会为任务编写工作流。
* [让 Claude 通过 ultracode 自主决定](#让-claude-通过-ultracode-自主决定)：设置 `/effort ultracode`，Claude 会为会话中每个实质性任务规划工作流。

你也可以运行已有的工作流命令：[内置工作流](#内置工作流)如 `/deep-research`，或你已[保存](#保存工作流以供复用)的工作流。

### 在提示词中请求工作流

要在不更改会话努力级别的情况下将单个任务作为工作流运行，请在提示词中包含 `workflow` 一词。

```text
Run a workflow to audit every API endpoint under src/routes/ for missing auth checks
```

Claude Code 会在输入中高亮显示该词，Claude 会为任务编写工作流脚本，而非逐轮处理。

如果运行达到预期效果，之后可以[将其保存为命令](#保存工作流以供复用)。

如果 Claude Code 高亮了该词但你并非有意触发，按 `alt+w` 可在本次提示词中忽略，或在光标紧跟高亮词时按退格键。要完全禁止该词触发，在 `/config` 中关闭 Workflow keyword trigger。

### 让 Claude 通过 ultracode 自主决定

Ultracode 是 Claude Code 的一项设置，将 `xhigh` [推理努力级别](/zh/model-config#调整努力级别)与自动工作流编排相结合。开启后，Claude 会为每个实质性任务规划工作流，而无需等待你的请求。

```text
/effort ultracode
```

开启 ultracode 后，Claude 自行判断任务是否需要工作流。单个请求可能连续产生多个工作流：一个用于理解代码，一个用于实施更改，一个用于验证。这适用于会话中的每个任务，因此每个请求比低努力级别使用更多 token 且耗时更长。

Ultracode 仅在当前会话有效，启动新会话时重置。返回常规工作时使用 `/effort high` 切回。支持 `xhigh` [努力级别](/zh/model-config#调整努力级别)的模型可用；其他模型的 `/effort` 菜单不会显示该选项。

### 在运行前审批计划

在 CLI 中，每次运行的提示会显示计划的阶段及以下选项：

* **Yes, run it**：开始运行
* **Yes, and don't ask again for `<name>` in `<path>`**：开始运行，此后在此项目中跳过此工作流的提示
* **View raw script**：决定前查看脚本
* **No**：取消

`Ctrl+G` 在编辑器中打开脚本。`Tab` 可在运行开始前调整提示词。

是否显示此提示取决于你的[权限模式](/zh/permission-modes)：

| 权限模式                                  | 何时提示                                                                                                                                    |
| :----------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Default、accept edits                      | 每次运行，除非你已为此项目中的该工作流选择了 **Yes, and don't ask again**                                                                               |
| Auto                                       | 仅首次启动时。任何 **Yes** 操作会将同意记录到用户设置中，后续启动不再提示。开启 ultracode 时完全跳过                                                     |
| Bypass permissions、`claude -p`、Agent SDK | 从不提示。运行立即启动                                                                                                                                |

在桌面应用中，审批卡片显示工作流名称、阶段列表和 token 用量提示，包含 **Once**、**Always** 和 **Deny** 操作。进度视图显示在后台任务侧边面板中。

你的权限模式仅控制上述启动提示。工作流生成的子代理始终以 `acceptEdits` 模式运行，并继承你的[工具允许列表](/zh/settings#权限设置)，无论会话模式如何。文件编辑自动审批。

不在允许列表中的 Shell 命令、网页抓取和 MCP 工具仍可能在运行中途提示你。为避免长时间运行中的中断，请在启动前将代理所需的命令添加到允许列表。

在 `claude -p` 和 Agent SDK 中没有交互对象，因此工具调用遵循你配置的权限规则，无需交互确认。

### 保存工作流以供复用

当 Claude 为你会重复执行的任务编写工作流时，可以将该运行的脚本保存为命令。例如在每个分支上运行的代码审查流程，之后每次运行相同的编排。

执行 `/workflows`，选择要保留的运行，按 `s`。在保存对话框中，Tab 切换两个保存位置：

* 项目中的 `.claude/workflows/`：与所有克隆仓库的人共享
* 主目录中的 `~/.claude/workflows/`：在所有项目中可用，仅自己可见

按 Enter 保存。工作流在未来的会话中以 `/<name>` 形式运行。

如果项目工作流和个人工作流同名，优先运行项目工作流。

## 工作流如何运行

工作流运行时在隔离环境中执行脚本，与你的对话分离。中间结果保存在脚本变量中，而非进入 Claude 的上下文。

运行时跟踪每个代理的结果，这使得运行在同一会话中[可恢复](#暂停后恢复)。

### 行为与限制

运行时施加以下约束：

| 约束                                                           | 原因                                                                                                            |
| :------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------- |
| 运行期间无用户输入                                                    | 仅代理权限提示可暂停运行。如需在阶段间审批，请将每个阶段作为独立工作流运行                                        |
| 工作流本身不能直接访问文件系统或 Shell                                   | 代理负责读写和执行命令。脚本负责协调代理                                                                       |
| 最多 16 个并发代理，CPU 核心有限的机器上更少                               | 限制本地资源使用                                                                                               |
| 每次运行最多 1,000 个代理                                                | 防止失控循环                                                                                                   |

## 管理运行

运行启动后，你可以从 `/workflows` 视图管理它，或从输入框下方的任务面板展开其进度行。

### 暂停后恢复

如果停止了运行，你可以恢复它：已完成的代理返回缓存结果，其余代理实时运行。从 `/workflows` 中选择已暂停的运行并按 `p` 恢复，或让 Claude 使用相同脚本重新启动工作流。

恢复仅在同一 Claude Code 会话内有效。如果在工作流运行期间退出 Claude Code，下次会话将重新启动工作流。

### 费用

工作流生成多个代理，因此单次运行可能比在对话中处理相同任务使用显著更多的 token。运行计入你计划的用量和速率限制，与任何其他会话相同。你可以随时从 `/workflows` 停止正在运行的工作流，不会丢失已完成的工作。

工作流中的每个代理使用你会话的模型，除非脚本将某个阶段路由到不同模型。要控制模型费用：

* 在大型运行前检查 `/model`，如果你通常在常规工作中切换到较小模型
* 在描述任务时要求 Claude 对不需要最强模型的阶段使用较小模型

### 关闭工作流

工作流在 CLI、桌面应用、IDE 扩展、使用 `claude -p` 的[非交互模式](/zh/headless)和 [Agent SDK](/zh/agent-sdk/overview) 中可用。相同的禁用设置适用于所有平台。

要为你自己关闭工作流：

* 在 `/config` 中关闭 Dynamic workflows。跨会话持久生效。
* 在 `~/.claude/settings.json` 中设置 `"disableWorkflows": true`。跨会话持久生效。
* 设置 `CLAUDE_CODE_DISABLE_WORKFLOWS=1`。启动时读取，因此适用于任何设置位置。

要为整个组织关闭工作流，在[托管设置](/zh/server-managed-settings)中设置 `"disableWorkflows": true`，或使用 [Claude Code 管理设置](https://claude.ai/admin-settings/claude-code)页面上的开关。

禁用工作流后，内置工作流命令不可用，`workflow` 关键词不再触发运行，`ultracode` 从 `/effort` 菜单中移除。
