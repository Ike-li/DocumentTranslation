# 调试您的配置

> 诊断为何 `CLAUDE.md`、设置、钩子、MCP 服务器或技能没有生效。使用 `/context`、`/doctor`、`/hooks` 和 `/mcp` 来查看实际加载了什么。

当 Claude 忽略了您配置的指令或功能未显示时，通常原因在于文件未加载、从与您预期不同的位置加载，或者被其他文件覆盖。本指南展示如何检查 Claude Code 实际加载了什么，以便您缩小问题范围。

如需了解安装、身份验证和连接问题，请参阅[排除安装和登录故障](/zh/troubleshoot-install)。

## 查看加载到上下文中的内容

`/context` 命令显示当前会话占用上下文窗口的所有内容，按类别分解：系统提示词、记忆文件、技能、MCP 工具和对话消息。请首先运行它，以确认您的 `CLAUDE.md`、规则或技能描述是否已加载。

要了解特定类别的详情，可使用相应的专用命令：

| 命令             | 显示内容                                                                                                     |
| :--------------- | :----------------------------------------------------------------------------------------------------------- |
| `/memory`        | 加载了哪些 `CLAUDE.md` 和规则文件，以及自动记忆条目                                                          |
| `/skills`        | 来自项目、用户和插件源的可用技能                                                                             |
| `/agents`        | 已配置的子代理及其设置                                                                                       |
| `/hooks`         | 活跃的钩子配置                                                                                               |
| `/mcp`           | 已连接的 MCP 服务器及其状态                                                                                  |
| `/permissions`   | 当前生效的允许和拒绝规则                                                                                     |
| `/doctor`        | 配置诊断：无效键、架构错误、安装健康状态                                                                     |
| `/debug [issue]` | 为会话启用调试日志，并提示 Claude 使用日志输出和设置路径进行诊断                                              |
| `/status`        | 活跃的设置来源，包括托管设置是否生效                                                                         |

如果某个记忆文件在 `/memory` 中缺失，请根据 [CLAUDE.md 文件如何加载](/zh/memory#how-claude-md-files-load)检查其位置。子目录中的 `CLAUDE.md` 文件仅在 Claude 使用 Read 工具读取该目录中的文件时按需加载，而非在会话开始时加载。

如果 `/memory` 确认文件已加载，但 Claude 仍未遵循某条特定指令，则问题很可能在于指令的编写方式，而非其是否加载。`CLAUDE.md` 适用于您会给予新队友的那类指导，例如项目规范、构建命令以及文件存放位置。

当指令含义模糊、存在多种解释方式，或两条文件给出相互冲突的指导，或文件已过长导致单条规则关注度下降时，遵循度会降低。[编写有效的指令](/zh/memory#write-effective-instructions)涵盖了能保持高遵循度的具体性、篇幅和结构模式。

  CLAUDE.md 与权限解决的是不同的问题。CLAUDE.md 告诉 Claude 你的项目如何运作，以便它做出正确的决策。[权限](/zh/permissions)和[钩子](/zh/hooks)则无论 Claude 如何决策，都会强制执行限制。使用 CLAUDE.md 来表达"本项目的规范做法是这样"。使用权限或钩子来设定安全边界以及任何绝不容许发生的事情——在此你需要的是保证，而不仅仅是指导。

## 检查已解析设置

设置在托管、用户、项目和本地作用域之间合并。当存在托管设置时，它们总是优先。在其他作用域中，作用域越近优先级越高，顺序为本地、项目、用户。某些设置也可以通过命令行标志或[环境变量](/zh/env-vars)设置，这会形成另一层覆盖。当某个设置似乎未生效时，您设置的值通常被另一个作用域或环境变量覆盖。

运行 `/doctor` 以验证配置文件并显示无效键或架构错误。当 `/doctor` 报告问题时，按 `f` 将诊断报告发送给 Claude，让它引导您修复问题。

运行 `/status` 以查看哪些设置源处于活动状态，包括托管设置是否生效。要了解对于给定键哪个作用域优先，请参阅[作用域如何交互](/zh/settings#how-scopes-interact)。

## 检查 MCP 服务器

运行 `/mcp` 以查看每个已配置的服务器、其连接状态以及您是否已批准它用于当前项目。服务器可能已正确定义，但由于一些常见原因仍未提供工具：

*   `.mcp.json` 中的项目范围服务器需要一次性批准。如果提示被关闭，服务器将保持禁用状态，直到您从 `/mcp` 批准它。
*   启动失败的服务器在 `/mcp` 中显示为失败。`command` 或 `args` 中的相对文件路径是常见原因，因为它们是相对于您启动 Claude Code 的目录解析的，而不是 `.mcp.json` 的位置。
*   显示为已连接但列出零个工具的服务器已成功启动，但未返回工具列表。从 `/mcp` 选择 **重新连接**。如果计数仍为零，运行 `claude --debug mcp` 以查看服务器的 stderr 输出。

有关配置位置和作用域规则，请参阅 [MCP](/zh/mcp)。

## 检查钩子

运行 `/hooks` 以列出为当前会话注册的每个钩子，按事件分组。如果您定义的钩子未出现，表示它未被读取：钩子位于设置文件中的 `"hooks"` 键下，而不是单独的文件中。

如果钩子出现但未触发，匹配器通常是原因。`matcher` 字段是一个使用 `|` 匹配多个工具名称的单一字符串，例如 `"Edit|Write"`。拼写错误的工具名称会静默失败，因为匹配器永远不会匹配。数组值是架构错误：Claude Code 显示设置错误通知，`/doctor` 报告验证失败，并且钩子条目被丢弃，因此不会出现在 `/hooks` 中。

对 `settings.json` 的编辑会在短暂的文件稳定延迟后在运行的会话中生效。您无需重启。如果 `/hooks` 在保存几秒后仍显示旧定义，请再次运行 `/hooks` 以刷新视图。

如果 `/hooks` 显示钩子但仍未触发，下一步是实时观察钩子评估。使用 `claude --debug hooks` 启动一个会话并触发工具调用。调试日志会记录每个事件、检查了哪些匹配器以及钩子的退出代码和输出。有关日志格式，请参阅[调试钩子](/zh/hooks#debug-hooks)；有关常见故障模式，请参阅[钩子故障排除](/zh/hooks-guide#limitations-and-troubleshooting)。

## 使用干净配置进行测试

如果针对性检查无法隔离原因，或者您的配置处于未知状态，请与一个未加载您常规设置任何内容的会话进行比较。将 [`CLAUDE_CONFIG_DIR`](/zh/env-vars) 指向一个空目录以绕过 `~/.claude` 下的所有内容，并从一个没有 `.claude` 文件夹、`.mcp.json` 或 `CLAUDE.md` 的目录启动，以便也跳过项目配置。
```bash
cd /tmp && CLAUDE_CONFIG_DIR=/tmp/claude-clean claude
```
清理会话没有用户或项目设置、钩子、MCP 服务器、插件或记忆。

* 如果您的组织部署了托管设置，它们仍然会生效，因为它们位于 `~/.claude` 之外的系统路径
* 在 Linux 和 Windows 上，系统会提示您重新登录，因为凭据存储在配置目录下
* 在 macOS 上，凭据位于钥匙串中，并会延续到清理会话

如果问题在此处消失，原因就在您实际的 `~/.claude` 或项目的 `.claude` 文件中的某个位置。将文件逐个复制到临时目录，或从您的项目中启动，以找出是哪个文件导致的问题。如果问题在清理会话中仍然存在，则原因在于您的用户和项目配置之外。运行 `/status` 以检查托管设置是否生效，查找影响 Claude Code 的[环境变量](/zh/env-vars)，然后查看[故障排除](/zh/troubleshooting)。

## 检查常见原因

大多数配置意外都源于少量位置和语法规则。在假设是错误之前，请先检查这些：

| 症状                                                                 | 原因                                                                                                                                         | 修复方法                                                                                                                                                                                                                                                         |
| :------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 钩子从不触发                                                         | `matcher` 是一个 JSON 数组而不是字符串                                                                                                         | 使用带有 `\|` 的单个字符串来匹配多个工具，例如 `"Edit\|Write"`。请参阅[匹配器模式](/zh/hooks#matcher-patterns)。                                                                                                                                                      |
| 钩子从不触发                                                         | `matcher` 值是小写的，例如 `"bash"`                                                                                                           | 匹配区分大小写。工具名称是首字母大写的：`Bash`、`Edit`、`Write`、`Read`。                                                                                                                                                                                          |
| 钩子从不触发                                                         | 钩子定义在独立文件中，而不是 `settings.json` 里                                                                                               | 项目或用户配置中没有独立的钩子文件。在 `settings.json` 的 `"hooks"` 键下定义钩子。只有[插件](/zh/plugins-reference#hooks)会加载单独的 `hooks/hooks.json`。请参阅[钩子配置](/zh/hooks)。                                                                                   |
| 全局设置的权限、钩子或环境变量被忽略                                   | 配置被添加到了 `~/.claude.json`                                                                                                               | `~/.claude.json` 存储应用状态和 UI 切换。`permissions`、`hooks` 和 `env` 应该放在 `~/.claude/settings.json` 中。这是两个不同的文件。                                                                                                                                |
| `settings.json` 中的某个值似乎被忽略                                  | 同一个键在 `settings.local.json` 中也被设置了                                                                                                 | `settings.local.json` 会覆盖 `settings.json`，两者都会覆盖 `~/.claude/settings.json`。请参阅[设置优先级](/zh/settings#how-scopes-interact)。                                                                                                                         |
| 技能在 `/skills` 中不显示                                             | 技能文件位于 `.claude/skills/name.md`，而不是在文件夹里                                                                                       | 使用包含 `SKILL.md` 的文件夹：`.claude/skills/name/SKILL.md`。                                                                                                                                                                                                      |
| 技能在 `/skills` 中显示，但 Claude 从不调用它                           | 技能的 frontmatter 中设置了 `disable-model-invocation: true`，或者其描述与您请求的措辞不匹配                                                  | 检查 `/skills` 中的徽章：标签为 "user-only" 意味着 Claude 不会自行触发它。请参阅[技能调用](/zh/skills)。                                                                                                                                                            |
| 子目录中的 `CLAUDE.md` 指令似乎被忽略                                  | 子目录文件是按需加载的，不是在会话开始时加载                                                                                                  | 它们在 Claude 使用读取工具读取该目录中的文件时加载，而不是在启动时，也不是在写入或创建文件时加载。请参阅 [CLAUDE.md 文件如何加载](/zh/memory#how-claude-md-files-load)。                                                                                              |
| 子代理忽略 `CLAUDE.md` 指令                                            | 内置的 Explore 和 Plan 代理会跳过 `CLAUDE.md`。自定义子代理以与主对话相同的方式加载它                                                          | 对于 Explore 或 Plan，请在您的委派提示词中重述指令。对于自定义子代理，请将关键指令放在代理文件正文中，这会成为代理的系统提示词。请参阅[启动时加载的内容](/zh/sub-agents#what-loads-at-startup)。                                                                         |
| 清理逻辑在会话结束时从不运行                                          | 未配置 `SessionEnd` 钩子                                                                                                                     | 在 `settings.json` 中添加一个 `SessionEnd` 钩子。请参阅[钩子事件列表](/zh/hooks#hook-events)。                                                                                                                                                                      |
| `.mcp.json` 中的 MCP 服务器从不加载                                    | 文件位于 `.claude/` 下或使用了 Claude Desktop 的配置格式                                                                                      | 项目 MCP 配置应放在仓库根目录的 `.mcp.json` 文件中，而不是在 `.claude/` 目录内。请参阅 [MCP 配置](/zh/mcp)。                                                                                                                                                         |
| 在 `settings.json` 的 `mcpServers` 下添加的 MCP 服务器从不显示          | `settings.json` 不会读取 `mcpServers` 键                                                                                                     | 在仓库根目录的 `.mcp.json` 中定义项目服务器，或者运行 `claude mcp add --scope user` 添加用户范围服务器。请参阅 [MCP 配置](/zh/mcp)。                                                                                                                                |
| 添加了项目 MCP 服务器但未显示                                          | 一次性批准提示已被忽略                                                                                                                       | 项目范围的服务器需要批准。运行 `/mcp` 查看状态并批准。                                                                                                                                                                                                             |
| MCP 服务器在某些目录下启动失败                                        | `command` 或 `args` 使用了相对文件路径                                                                                                       | 对本地脚本使用绝对路径。像 `npx` 或 `uvx` 这样在您 `PATH` 上的可执行文件可以直接使用。                                                                                                                                                                             |
| MCP 服务器启动时缺少预期的环境变量                                     | 变量在 `settings.json` 的 `env` 中，这不会传播到 MCP 子进程                                                                                  | 改为在 `.mcp.json` 中为每个服务器设置 `env`。                                                                                                                                                                                                                     |
| `Bash(rm *)` 拒绝规则未能阻止 `/bin/rm` 或 `find -delete`               | 前缀规则匹配的是字面命令字符串，而不是底层的可执行文件                                                                                       | 为每个变体添加显式模式，或者使用 [PreToolUse 钩子](/zh/hooks-guide)或[沙箱](/zh/sandboxing)来提供硬性保证。                                                                                                                                                          |
